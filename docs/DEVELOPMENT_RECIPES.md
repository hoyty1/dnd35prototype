# Development recipes

Step-by-step procedures for the common changes in this project: which files to touch, in which order, and which traps earlier commits fell into. It supersedes the retired how-to docs listed in [archive/INDEX.md](archive/INDEX.md); where they disagree with this doc or the code, the code wins.

- Line numbers are as of 0dd8e76 and drift. Grep the `Class.Method` name first; use the line only as a hint.
- Runtime claims come from reading the code. Nothing here was run in Play mode for this revision unless stated.
- Bugs mentioned under "Pitfalls" are the ones you will hit while following the recipe. The full list is in [KNOWN_ISSUES.md](KNOWN_ISSUES.md); issue IDs link to their area file under `issues/`.
- Example commits are short hashes; read them with `git show --stat <hash>`. Many of them use pre-reorganisation paths (`Assets/Scripts/Core/`, `Identifiers/`, `Inventory/`, `Magic/Spells/Databases/`, `UI/Panels/`). Use the current paths given here.

## Golden rules (apply to every change)

1. **Compile after every edit.** Run `bash tools/compile_check.sh` from the repo root (headless, about 5 s; `VERBOSE=1` lists warnings; see [TESTING.md](TESTING.md)). Baseline at 0dd8e76: 0 errors, 508 warnings. Any error, or a jump in the warning count, is a regression. The history has repeated waves of commits that did not compile (f706ac6 "127+ compilation errors", e8e103b, 0dd2d61, 167daee, 66997bc, afd2df5, 71b869b, 0fec1eb), mostly from invented members. Grep every member you call before you call it.
2. **C# 9 only.** Unity 6000.4.0f1 compiles with LangVersion 9.0. No C# 10+ syntax (file-scoped namespaces, `global using`, `record struct`).
3. **Global namespace.** Game code is in the global namespace. Exceptions: the id constant classes `SpellNames`, `ItemIDs`, `WondrousItemNames` and `RingNames` live in `DND35e.Identifiers` (add `using DND35e.Identifiers;`; `RodNames` is global), and tests use `Tests.<Area>` namespaces. `GameManager` is one partial class across about 52 files; put new GameManager code in the partial for its domain.
4. **Never mutate database templates.** `SpellDatabase.GetSpell`, `ItemDatabase.Get` and `NPCDatabase.Get` return the shared registered instance. Clone first: `SpellData.Clone()`, `ItemDatabase.CloneItem(...)`, `NPCDefinition.Clone()`.
5. **New fields must be copied by hand.** A new `ItemData` field must be copied in `ItemDatabase.CloneItem(string)` (`Assets/Scripts/Equipment/Items/ItemDatabase.cs:1700+`), and in `ItemBuilder.CopyBaseProperties` for builder-made items. A new `NPCDefinition` field needs `NPCDefinition.Clone` and the template `CopyDefinitionFields` lists. Otherwise the value is lost on every clone (store purchase, NPC equip, spawn).
6. **Commit `.meta` files with their assets.** Every asset's `.meta` is versioned (since 2026-10-03); it holds the GUID that scenes and assets use to reference it. Unity creates the `.meta` for a new script or asset when it imports it, so after adding files outside Unity, let Unity import them and commit the generated `.meta` files. Move or rename an asset together with its `.meta` (`git mv` both). Do not hand-write `.meta` files. The compile check does not import assets or create metas.
7. **Log through the combat log.** `CombatUI?.ShowCombatLog(CombatLogHelper.X(...))`, plus a tagged `Debug.Log("[System] ...")` for the Console. See [Add a combat-log message](#add-a-combat-log-message).
8. **Add or extend a static `RunAll()` test suite** under `Assets/Scripts/Tests/<Area>/`. There is no Unity Test Framework and no asmdef; the committed runner `Tests.Runner.StaticSuiteRunner` finds every `*Tests` class with a static `RunAll()` and runs it (Tools > DND Tests, or `RunFromCommand` through the Unity MCP; [TESTING.md](TESTING.md) section 3). Add the suite's entry (`needs`, `passed`/`failed`, and known failures with issue IDs) to `tools/tests/static-suites.json`; when a change fixes or breaks a listed assertion, update the entry in the same change so that both passes stay at verdict OK. Build actors with `TestHelpers.CreateCharacter` (or `CharacterController.Init`) at explicit adjacent positions, not by assigning `controller.Stats` (TST-029).
9. **Test in Play mode** through the F12 Spell Testing Panel (PC spells only), a test encounter preset (see [Add an encounter preset or test scenario](#add-an-encounter-preset-or-test-scenario)), or the scenario harness: a definition in `Assets/Scripts/Tests/Scenarios/Catalog/` or one built inline in an MCP CommandScript, run with `Tests.Scenarios.ScenarioHarness.Start` in a fresh Play session ([TESTING.md](TESTING.md) 3.4). If you could not, say "not verified in Play mode" in the commit message.
10. **Expect silent failures.** Most registries fail quietly: a missing switch case defaults, an uncalled `RegisterX()` still compiles, a misspelled name string never matches, a duplicate id overwrites. After a change, check the init log count or the spawn log. Update this doc in the same commit when a recipe changes.

# Magic

## Add a spell (data)

Use when a spell needs to exist in `SpellDatabase` (always the first step for a new spell).

1. Add the id constant to `Assets/Scripts/Spell/Data/SpellNames.cs` (class `SpellNames`, alphabetical, snake_case value, `/// <summary>Name (spell id: my_spell)</summary>`). Ignore the `SpellID` enum (`Spell/Data/SpellID.cs`): only `IdentifierExtensions`, `EnumTest` and the unused `ItemData.ConsumableSpellIDEnum` read it.
2. Add `Register(new SpellData { ... });` inside `RegisterSpells<Letter>()` in `Assets/Scripts/Spell/Database/SpellDatabase_<FirstLetter>.cs` (templates: Magic Fang in `_M`, Know Direction in `_K`). `SpellDatabase.Init` (`SpellDatabase.cs:33-86`) calls `RegisterSpellsA..Z`, but there are no Q, X or Y files or calls. For those letters create `SpellDatabase_Q.cs` (`public static partial class SpellDatabase { private static void RegisterSpellsQ() { ... } }`) and add the call to `Init` in alphabetical position.
3. Fill the `SpellData` fields (`Spell/Data/SpellData.cs:43-500`):
   - Identity: `SpellId = SpellNames.X`, `Name`, `Description` (cite the PHB page), `SpellLevel`, `School` (string), `ClassList` (string[]; `Register` adds Sorcerer for Wizard and vice versa).
   - Targeting: `TargetType` (`SpellTargetType.Self/SingleEnemy/SingleAlly/Touch/Area`), `RangeCategory` (its setter calls `SpellRanges.Configure`), `IsTouch/IsMeleeTouch/IsRangedTouch`; areas use `AoEShapeType/AoESizeSquares/AoERangeSquares/AoEFilter`.
   - Effect: `EffectType` (`SpellEffectType`), `DamageDice` (die SIDES), `DamageCount`, `BonusDamage`, `DamageType` ("fire", "cold", ...), `AutoHit/MissileCount`, `HealDice/HealCount/BonusHealing`, `Buff*` fields with `BuffBonusType` + `BonusTypeExplicitlySet`. Dice that scale with caster level go in `ScalingDicePerLevels`/`ScalingDiceMax` ("1d6 per level, max 10d6": 1 and 10, with `DamageCount = 1`) and a "+1 per level (max +N)" bonus in `LevelBonusPerLevels`/`LevelBonusMax`; the base `BonusDamage`/`BonusHealing` is the fixed part only. A positive- or negative-energy spell (cure, inflict) sets `Energy`, so it inverts on undead. `SpellDiceRules` reads them for every cast path, the AI estimates and the UI (SPL-005).
   - Defenses: `AllowsSavingThrow`, `SavingThrowType` ("Reflex"/"Will"/"Fortitude"), `SaveHalves`, `SpellResistanceApplies`, `IsMindAffecting`.
   - Duration and casting: `DurationType/DurationValue/DurationScalesWithLevel` (the PHB duration; `SpellDurationRules` turns it into rounds, per caster level when `DurationScalesWithLevel`; cite the PHB page in a comment; a `Concentration` spell also sets `ConcentrationTailRounds`/`ConcentrationTailScalesWithLevel` for "concentration + N rounds" and `ConcentrationMaxRounds`/`ConcentrationMaxScalesWithLevel` for "up to X", in rounds, which `ConcentrationRules` reads; batch 11 step 16) and, for a timed duration, also `BuffDurationRounds` so Extend is offered (see pitfalls), `ActionType` (the casting time from the PHB header, charged by the cast core on every path since batch 11 step 12, `CastActionRules`: `Standard` for 1 standard action, `FullRound` for a 1-round casting time, `Free` for a free action such as Feather Fall, which also counts as the round's quickened spell; a casting time over 1 round has no value yet, SPL-167), `ProvokesAoO`, `HasVerbalComponent/HasSomaticComponent` (default true; the material, focus and divine focus flags are not set in the block: add the spell's PHB Components line, for example `{ SpellNames.MY_SPELL, "V, S, M/DF" }`, to `Spell/Data/SpellComponentLines.cs`, which `Register` applies; a priced material component or focus also goes in `SpellComponentRegistry.RegisterDefaultComponents`, with an item id when an item stands for it; `Tests.Magic.SpellComponentRulesTests` fails on a spell with no line; batch 11 step 17), `IsPlaceholder` + `PlaceholderReason`.
4. Other class lists at a different level: `RegisterClassSpellAlias("my_spell_brd", SpellNames.MY_SPELL, "Bard", 2);` (`SpellDatabase.cs:111-123`). Plain aliases: `RegisterAlias(alias, canonical)`. Domain spells: add `{ level, SpellNames.X }` to the domain dictionary in `new DomainData(...)` in `Assets/Scripts/Character/Religion/DomainDatabase.cs`; `SpellDatabase.AnnotateDomainAvailabilityFromDomainDatabase` adds the Cleric availability.
5. Descriptors: `AnnotateSpellDescriptors` (`SpellDatabase.cs:149+`) auto-detects Fire/Cold/Acid/Electricity/Sonic/Force from `DamageType`, Divination from `School`, and Healing only for `EffectType` Healing with School Conjuration. Good/Evil/Lawful/Chaotic/Fear/MindAffecting/Death/Light/Darkness need an explicit `SetDescriptor(SpellNames.X, SpellDescriptor.Y);` there (domain caster-level boosts depend on them).
6. Check `Assets/Scripts/AI/SpellCategoryClassifier.cs`. `ReclassifyAll` (called at `SpellDatabase.cs:75`) overwrites `EffectType` at Init for ids in its Control/Summon/Dispel/Wall/Illusion/Escape/Divination/Utility sets (`:115-193`), and turns any Debuff with no damage + Will save + `IsMindAffecting` into Control (`:96-103`). The final `EffectType` decides dispatch (next recipe).
7. Optional exposure: scroll loot `TreasureData.ScrollSpells` (`TreasureGenerator/TreasureData.cs:1696`; keys `arcane_N`/`divine_N`, values are lowercase DISPLAY names), staves (`Spell(SpellNames.X, "Name", level, chargeCost)` in `Equipment/Staves/StaffDatabase.cs`), class default spellbooks (`Character/Classes/WizardClass.cs:133-151`), costly components (`SpellComponentRegistry` in `Spell/Casting/SpellComponentSystem.cs:184`). Scrolls, potions and wands are generated automatically ([Add a scroll, potion or wand](#add-a-scroll-potion-or-wand)).
8. Compile, then confirm in Play mode that `[SpellDatabase] Initialized with N spells` rises by one.
9. The spell routing golden suite (`Tests.Magic.SpellRoutingGoldenTests`) now fails with `spell routing added: my_spell`: check the new row (effect type after reclassification, target type, shape, `ReachesApplySpellBuff`, PC branch, NPC refusal), regenerate `tools/tests/spell-routing-golden.json` with `Tests.Magic.SpellRoutingGoldenTests.WriteGolden()` through the Unity MCP, raise the suite's `passed` in `tools/tests/static-suites.json` by one, and list the spell in the commit body. Any change to an existing spell's routing data does the same: regenerate only on purpose, never to silence a diff you cannot explain ([TESTING.md](TESTING.md) 3.5).
10. **Where its effect goes.** Every cast of it, from the spell menu, a scroll, a wand, the F12 panel, a held charge or the AI, is one `SpellCastRequest` run by the one cast core (`ExecuteCast`), so there is one place for each part and nothing to add per caster: if the data describes the effect, stop; a special single-target effect is one line in the SpellId registry (`BuildSingleTargetHandlers`, [the next recipe](#implement-a-single-target-touch-or-self-spell-effect) step 3), an area effect one line in the area registry (`BuildAreaHandlers`, [Implement an area spell](#implement-an-area-spell) step 4), each with its manifest row in `Tests.Magic.SpellHandlerRegistryTests`; a tracked effect that is not Buff/Debuff/Control/Illusion/Wall after reclassification needs its id in `SpellEffectRouting` to reach `ApplySpellBuff` (the golden suite above pins the routing). Then add a seeded rules scenario ([Add a combat scenario](#add-a-combat-scenario)) that casts it on the path that matters, a Ui caster and an AI or Scripted one when both can cast it, and run it through the Unity MCP.

Files: `Spell/Data/SpellNames.cs`, `Spell/Database/SpellDatabase_<Letter>.cs`, `Spell/Database/SpellDatabase.cs`, `Character/Religion/DomainDatabase.cs`, `AI/SpellCategoryClassifier.cs`; optionally `TreasureGenerator/TreasureData.cs`, `Equipment/Staves/StaffDatabase.cs`, `Spell/Casting/SpellComponentSystem.cs`. Examples: 571fe1f, b2f2f1d, f165fd7, 6921d93, aa1ad37, 88043b2, 5b98444, 7509633, f706ac6.

Pitfalls:
- The generic damage path (`SpellCaster.Cast`, `Spell/Casting/SpellCaster.cs:416-520`) rolls a FIXED `DamageCount` and never scales with caster level. Burning Hands is registered as 3d4 at every CL (`SpellDatabase_B.cs:393-407`) and no handler overrides it. CL-scaled spells need a custom handler.
- Extend reads the duration fields: `MetamagicData.CanExtend` and its effect share `SpellDurationRules.IsExtendable` (`DurationType` not Instantaneous, Permanent or Concentration; set `SpellData.HasTimedAftereffect` for an "Instantaneous/..." line such as Death Knell's). A handler that rolls dice for the spell rolls them through `SpellDiceRules.RollFor(spell, ...)` (or `ctx.RollSpellDice`), with a spec in `CustomSpellDice`, so Empower and Maximize apply; a duration it computes itself goes through `SpellDurationRules.Extended(spell, rounds)`; an area or effect that rolls later keeps the cast's metamagic (`PersistentAreaEffect.Metamagic`, `GameManager.ActiveSpellMetamagic`) (batch 11 step 19). Setting only `BuffDurationRounds` is a mistake: `SpellDatabase.Register` converts it to fixed rounds (or 1 hour/level for -1), logs a warning, and `Tests.Magic.SpellDurationRulesTests` fails while any spell needs that (SPL-002). For a rolled or compound PHB duration ("1d6+2 rounds", "Concentration + 1 round/level") also set `DurationText`, which only the display reads.
- A handler that keeps its own state (a `CharacterStats` flag or an `*EffectData`) takes its rounds from `SpellCastingHelper.CalculateDuration(spell, casterLevel)`, not a hand-written formula, and ends that state where the tracked effect ends (`StatusEffectManager.RemoveEffect`); see the side-state table in [architecture/spells.md](architecture/spells.md#durations-and-ticking).
- `GetSpell` returns the shared instance. `Clone()` (`SpellData.cs:511`) deep-copies `AvailableFor` and `AppliedMetamagics` but shares the `ClassList` array. Shield of Faith mutates the database entry in place (`GameManager.SpellCasting.cs:7742-7743`).
- `RegisterClassSpellAlias` only works if the canonical spell is already registered (else a warning at `SpellDatabase.cs:121`). Letter files run A to Z, so put the alias in the canonical spell's file or a later one.
- Aliases resolve only through `SpellDatabase.GetSpell`; code comparing `spell.SpellId == SpellNames.X` sees the canonical id.
- Check class lists and levels against the PHB; 5b98444 and 88043b2 had to fix wrong ones.
- The `SpellDatabase.cs` header comment ("~140 spells, Wizard/Cleric 0-2") is stale: there are 292 registered spells (`Register(new SpellData ...)` calls), about 133 class aliases, 25 plain aliases and 47 placeholders.

## Implement a single-target, touch or self spell effect

Use when the spell needs behavior beyond what the generic cast path does with its data fields.

1. **Check whether data is enough.** `GameManager.PerformSpellCast` hands the cast to the staged cast core (`ExecuteCast`, `Spell/Resolution/GameManager.CastCore.cs`), whose Resolve stage (`CastStageResolve`) calls `SpellCaster.Cast`, which does the touch attack, SR, save, typed damage (`ApplyIncomingDamage` with a `DamagePacket`) and healing. If `SpellEffectRouting.ReachesApplySpellBuff` is true (`appliesTrackedEffect`: `EffectType` Buff/Debuff/Control/Illusion/Wall after reclassification, or a spell listed in `Spell/Casting/SpellEffectRouting.cs`), the save did not negate it and no handler claimed it, `ApplySpellBuff` runs; with no branch for the spell its last block, the generic `StatusEffectManager.AddEffect` branch, which applies `BuffAttackBonus/BuffDamageBonus/BuffACBonus/BuffSaveBonus/BuffSkillName+BuffSkillBonus/BuffSpeedBonusFeet/BuffStatName+BuffStatBonus/BuffTempHP` with duration and the PHB stacking rules (set `BuffBonusType` and `BonusTypeExplicitlySet` to the spell's real bonus type: the attack, damage, save, skill, speed and ability bonuses go to `CharacterStats.Bonuses` with that type; `SpellData.AllSkillsBuffSkillName` means every skill). If that describes the spell, stop.
2. **Write the handler** in `public partial class GameManager` in `Assets/Scripts/Spell/Resolution/GameManager_Spells_<FirstLetter>.cs` (files exist for A-I, K, L, M, N, P, R, S, V, W plus Cantrips/MagicFang/Phase1/Phase2/Shared; create a new partial for other letters). Two shapes:
   - Shape A, post-cast effect: `private bool TryResolveMySpellSpellEffect(CharacterController caster, CharacterController target, SpellData spell, SpellResult result)` that returns false unless `spell.SpellId` matches, and whose first statement after that guard is `CastStageTrace.Mark(caster, spell, CastStageTrace.Handler, nameof(TryResolveMySpellSpellEffect));` (the inert cast-stage side channel, batch 11; [TESTING.md](TESTING.md) 3.5) (templates `TryResolveDeathKnellSpellEffect` `GameManager_Spells_D.cs:323`, `TryResolveDimensionalAnchorSpellEffect` `:681`).
   - Shape B, tracked buff/debuff: `private ActiveSpellEffect ApplyMySpellEffect(caster, target, spell, spellComp, SpellResult castResult = null)` dispatched from `ApplySpellBuff`. `castResult` is the cast's `SpellResult` (null for area casts and the harness): read its save and spell resistance instead of rolling them again, and roll them yourself only when it is null. A handler that rolls damage or healing dice applies `castResult.Metamagic` (Empower, Maximize) through `SpellDiceRules.Roll`, as `ApplyDisintegrateEffect` does. A bonus that scales with caster level belongs in `StatusEffectManager.AddEffect` (it receives the caster level; Barkskin), so item paths that call `AddEffect` directly get it too.
3. **Register Shape A: one line.** In `BuildSingleTargetHandlers` (`Spell/Resolution/GameManager.SpellHandlerRegistry.cs`) add `Add(nameof(TryResolveMySpellSpellEffect), HandlerGate.SuccessNotNegated, (c, t, s, r) => gm.TryResolveMySpellSpellEffect(c, t, s, r), SpellNames.MY_SPELL);` with the gate the cast must pass before the handler runs (`None`: every cast, even a failed one; `Success`: `result.Success`; `SuccessNotNegated`: also no negating save). `PerformSpellCast` and `TryNPCPerformSpellCast` both run it through `RunSingleTargetHandlers` (the NPC path since batch 11 step 6); a handler that returns true claims the cast, so `ApplySpellBuff` does not also run (use `AddContinuing` for a handler that adds to the cast and lets the buff step run, as Shield Other does). Add the row to the manifest in `Tests/Magic/SpellHandlerRegistryTests.cs`: handler name, gate, ContinueToBuff and the spell id the method's own guard accepts (it fails on an unregistered handler, a spell id claimed twice, or a gate, flag or id that differs from the row). Nothing to add on the NPC side; write the handler against the caster it is given (never ActivePC or IsControllable; a choice it reads is a `CastChoices` field of its cast's request, through its read-only `_pending*` view, and it never writes one), and if it needs a choice the AI cannot make yet, give the choice a `CastChoices` field both deciders fill (Dimension Door's `Destination`, batch 11 step 27), or until the AI can make it add the spell to `AISpellcastingStrategist.NeedsCasterChoiceAiCannotGive` (AI-071) and to that suite's exclusion check.
4. **Wire Shape B into `ApplySpellBuff` above its last block** (`// ===== GENERIC TRACKED EFFECT`), which returns for every spell. `ApplySpellBuff` is shared by the PC chain, the NPC chain and the generic AoE loop. If the spell's effect type after `SpellCategoryClassifier.ReclassifyAll` is not Buff/Debuff/Control/Illusion/Wall, add its ID to `SpellEffectRouting` (both single-target chains read it; the AoE loop routes only the tracked types, `SpellEffectRouting.IsTrackedEffectType`), and for a Healing or Damage spell set `HealingResolvedByHandler` or `DamageResolvedByHandler` in its data so `SpellCaster.Cast` does not heal or damage first (SPL-037).
5. **Use the shared helpers; never hand-roll rules.**
   - Caster level and duration: `SpellCastingHelper.GetEffectiveCasterLevel(caster, spell)` (= `CasterLevelRules.ForCaster`), `CalculateDuration(spell, cl)` (`Spell/Casting/SpellCastingHelper.cs:103, :144`).
   - DC: inside a GameManager handler `GetSpellSaveDC(caster, spell)` (adds the pending cast's Heighten; never the static `SpellUtilities.GetSpellSaveDC` there, which drops it); elsewhere `SpellSaveDCRules.Compute(caster, spell, metamagic)` or `SpellUtilities.GetSpellSaveDC`. All honor a pre-baked `spell.SaveDC` from scrolls/wands. A spell-like ability uses `SpellSaveDCRules.ComputeSpellLikeAbility` (MM p.315), a magic item `SpellSaveDCRules.ForMagicItem` (DMG p.214). A special DC built on the spell's DC (Dismissal: DC - HD + CL, PHB p.222) starts from it.
   - Defenses: a spell's save is `RollSpellSave(caster, target, spell, SaveType.X, dc)` inside a GameManager handler, or `ctx.RollSave(target, SaveType.X, dc, diceLabel)` where the handler has the `CastContext` (an area handler's registry lambda passes it): the target may give up its save (PHB p.177, its own decider; `SaveResult.Forgone`) and the save carries the target's situational bonuses and the spell-and-caster ones (`SaveContext.ForSpellCast`: the protection ward, Charm Person and Charm Monster, Hideous Laughter, Lullaby; batch 11 step 18), through the one save roll (`SaveRollRules`: natural 1 and 20, Luck, countersong; batch 12 step 10). A save outside a spell (a creature ability, an item, a disease) calls `SaveRollRules.Roll(stats, SavingThrowType.X, dc, SaveContext..., diceContext)` (or `SavingThrowResolver.ResolveSave`, built on it) with a context such as `SaveContext.CreatureAbility(label, source)` or `SaveContext.Effect(label, source)`; never roll a save's d20 by hand. Code outside GameManager (an area-effect class such as `GustOfWindEffect`) calls `SpellSaveRules.RollSave(caster, target, spell, SaveType.X, dc)` and `SpellSaveRules.RollSpellResistance(caster, target, spell, label, cl)` instead. Spell resistance is `ctx.RollSpellResistance(target, diceLabel)` or `SpellSaveResolver.RollSpellResistance(caster, target, cl)` (d20 + caster level + Spell Penetration, one rule, SPL-122), only when the spell allows SR. `SpellSaveResolver.ApplyEvasion / ApplyBlinkHalving` (`Spell/Casting/SpellSaveResolver.cs`) finish a Reflex-half save. A hand-rolled save outside a spell uses `SaveRules.Modifier(target.Stats, SavingThrowType.X, context)`, never `Stats.WillSave` plus extras (CHR-018).
   - Damage: `DealDamage(target, raw, DamagePackets.Spell(spell.Name, DamageType.Fire, savedForHalf))` (`_Core/GameManager.Damage.cs`, SPL-004) runs `ApplyIncomingDamage` (immunity, resistance, Fire Shield, temporary HP; no DR for spells, MM p.307), the concentration check and the death handling (damage dealt by creatures the spell summons, such as Insect Plague's locust swarms, is their own attack: `DamagePackets.CreatureAttack`, which DR reduces, MM p.316, owner interpretation 2026-10-11); log `dealt.FinalDamage` and `DescribeMitigation(dealt)`. `savedForHalf` is true only after a successful Reflex save for half (Fire Shield, PHB p.230). A handler whose pipeline runs the after-damage checks from `SpellResult` (Searing Light, Vampiric Touch) uses `ApplyDamagePacket` and sets `result.DamageDealt` and `result.TargetKilled`. A `SpellEffectType.Damage` spell whose handler deals the damage sets `DamageResolvedByHandler = true` in its SpellData (keep the dice for AI scoring and the UI), or `SpellCaster.Cast` deals the generic dice first and the target takes both (Searing Light, Spiritual Weapon, Produce Flame; SPL-124); its registry line runs it on both single-target paths (batch 11 step 6). Damage of two types (Ice Storm) is one packet per type, then one `AfterDamageTaken`. A `PersistentAreaEffect` calls `DealSpellDamage(character, raw, type)`. The caller runs `EvaluateCombatEnd` once the whole effect has resolved: every `PerformAoESpellCast` dispatch block of a damage handler, the single-target PC pipeline (when `result.TargetKilled` or the target is out of the fight), swarm damage, breath weapons, ranged specials and the Bombardier spray do; NPC single-target casts, Heat Metal ticks and the scroll mishap rely on the next `ShowActionChoices` or turn-boundary check. Never `Stats.TakeDamage` or `CurrentHP -=`.
   - Tracked effect: `StatusEffectManager.AddEffect`. Conditions: `_conditionService.ApplyCondition(target, type, rounds, source: caster, sourceNameOverride: spell.Name, sourceCategory: "Spell", sourceId: spell.SpellId)` (pattern `:6379-6386`).

## Add an action

Use for a combat action both sides take: a PHB Table 8-2 row or a creature ability. The catalog is `Combat/Actions/` ([Combat actions](architecture/combat-actions.md)); the plan is `docs/designs/action_catalog_batch13.md`.

1. **Id.** Add a constant to `ActionIds` (`Combat/Actions/ActionIds.cs`).
2. **Entry.** Add one `Def(...)` line to `ActionCatalog.Build` (`Combat/Actions/ActionCatalog.cs`):
   - the Table 8-2 cost (`ActionCostType`) and provocation (`ProvokeRule`), read from PHB p.141 with the extract's offset columns realigned (the class summary lists the realigned rows); `ByMovement` when only the movement provokes;
   - the target kind, the roles, a `RulesRef` that names the book and page, the status and its issue IDs;
   - `.Costs(rule)` for a per-actor cost (a feat, a casting time, a single-action turn), `.For(predicate)` for an action only some creatures have, `.AsManeuver(type)` for a `SpecialAttackType` (its cost must agree with `ManeuverActionCost.For`);
   - `.Run(executor, UiAfter, seconds)` once an executor exists.
3. **Executor.** Implement `IActionExecutor` in `Combat/Actions/Executors/`:
   - `CanStart(actor)` and `CanExecute(ctx)` are pure and return `Legality` with its `LegalityBar` (wrap an old check with `ActionLegality.FromDisabledReason`, `FromCheck` or `FromCast`);
   - `Execute(ctx, outcome)` is a coroutine: pay through `ActionCosts.TryPay` or the core you wrap, resolve provocation through `GameManager.ResolveActionProvocation` (the decider confirms; it never ends the turn), set `Performed`, `Refusal`, `ActorDown`, `CoreOutcome`;
   - read whose choices they are from `ctx.Source` and ask `ctx.Decider`; never call `ShowActionChoices`, `AfterAttackDelay`, `EndActivePCTurn` or `DelayedEndActivePCTurn`, and never read `IsControllable`, `ActivePC` or `IsPlayerTurn` (ActionCatalogTests scans the folder);
   - delegate to a live caller's entry point with its whole prelude (its gates, ward breaks, declarations), not to the raw core it wraps, and set `RefusalLogged` when that core logs its refusal;
   - a private GameManager member is reached through a thin forwarder in `Combat/Actions/Executors/GameManager.ActionCores.cs` (`ActionCore_*`) or an unrouted `Try*ForAI` core; never call a `*ForAI` wrapper that itself routes through `RunAIAction` (since batch 13 step 6 most do: `NPCPerformAttackForAI`, `MoveCharacterAlongComputedPathForAI`, `NPCExecuteBreathWeaponForAI` and the rest listed in combat-actions.md), or the run recurses;
   - an executor over a core that continues the PC UI itself sets `CoreOwnsUi` (as the cast executor does with the UI decider), or the entry's `UiAfter` is `None`; the PC runner then adds no follow-up.
   Status: `Delegating` over a finished core (the runner trusts its refusals), `Extracted` or `New` otherwise (the AI runner pre-checks `CanExecute` and a refusal spends nothing).
4. **Callers.** The PC panel calls `GameManager.RunPlayerAction(ctx)` (it applies `UiAfter`); a new PC button is built in `SceneBootstrap` and wired to a `GameManager.On<Action>ButtonPressed` that calls it, and `ActionButtonPanel` takes the button's state from the executor's `CanStart` and hides it in `HideAllActionButtons` (and `HideNonGrappleActionButtons` when a grappler cannot take it); total defense is the example (batch 13 step 4); the AI, the harness and a forced PC turn yield `RunAIAction(ctx, outcome)`. An existing AI wrapper that returned its core's enumerator routes with `RunAIActionInline` (no frame added), a synchronous AI call site with `RunAIActionNow`; keep the wrapper's name and its core's GameManager method names, because the scenario trace records the GameManager frames that end a combat (`ScenarioTrace.CallerFrames`) and a renamed core moves the hash. The legal set (`ActorActionSet`) reads the entry's `CanStart`, so a new entry is in it at once; a PC button that disagrees with it needs a row in `ActionPanelParityTests.KnownMismatches` with the step or issue that resolves it. Build the context with `ActionContext.For(id, actor, source, target)` and put a prebuilt core request in `CoreRequest`.
5. **Tests.** Add the row to `ActionCatalogTests.Golden` (and the button to `ActionPanelParityTests.ButtonToAction` when it has one); add scenario twins (`-ui`, `-ai`) when both sides can act (`Step.Action(actionId, ...)` runs any entry on either side), in `Tests/Scenarios/Catalog/ActionCatalogScenarios.cs` (created in batch 13 step 4 for total defense) unless a subsystem file such as `ChargeCoreScenarios.cs` fits better ([Add a combat scenario](#add-a-combat-scenario)).
6. **Docs.** The entry's row in `docs/architecture/combat-actions.md`, and the status in `docs/systems/AI_ACTION_COVERAGE.md`.

Pitfalls:
- An AI weapon attack is declared only on a target the attack guard allows (`AI/AiAttackGuard.cs`, decision D1; batch 13 step 5): a new AI routine or behaviour picks its attack target with `AIService.SelectGuardPassingTarget` (or asks `AiAttackGuard.Passes`), and when nothing passes it runs the profile's alternatives (`AIService.RunOutOfReachAlternatives`, `AIProfile.GetOutOfReachAlternatives`); never widen a weapon's reach or range with a spell's.

# Items and economy

All item kinds end up as `ItemData` in `ItemDatabase`; rings, rods and wondrous items are injected by their own databases during `SceneBootstrap` (order: `ItemDatabase.Init`, ring/wondrous/rod `RegisterAll...InItemDatabase`, `SpellDatabase.Init`, `CraftableItemRegistry.Init`; `_Core/SceneBootstrap.cs:1060-1080`). Golden rule 5 (copy new fields in `CloneItem`) applies to every recipe here.

## Add a mundane weapon, armor or shield

1. Add a snake_case id constant to `Equipment/Items/ItemIDs.cs` (`DND35e.Identifiers`). `ItemDatabase._items` is case-sensitive.
2. Register it in the matching `ItemDatabase.RegisterSimpleMeleeWeapons / RegisterSimpleRangedWeapons / RegisterMartialMeleeWeapons / RegisterMartialRangedWeapons / RegisterLightArmor / RegisterMediumArmor / RegisterHeavyArmor / RegisterShields`, following the local style:
   - Simple melee weapons: `ItemBuilder.Weapon(id).Named().Desc().Simple().Melee().Light()|OneHanded()|TwoHanded().Damage(count, sides, "type").Crit(min, mult).Reach(...)/Thrown(ft).Weight().Price().Icon().Build()`.
   - Body armor: `ItemBuilder.Armor(id).AC().MaxDex().CheckPenalty().SpellFailure().LightArmor()|MediumArmor()|Heavy().Metal()|NonMetal().Tags()`.
   - Simple ranged, martial melee, martial ranged and shields: a literal `new ItemData { ... }` (ranged: `RangeIncrement`, `RequiresAmmoType`, `RequiresReload`, `IsLoaded`, `ReloadAction`).
3. Slot: the builders set `EquipSlot.EitherHand` (weapon), `Armor`, `LeftHand` (shield); set the same yourself on literals. `Register` syncs and clamps `EnhancementBonus` (0-5) and infers size, light/two-handed, reach and attack range.
4. Price: `BasePriceGp` (`.Price(gp)`) or an entry in `ApplyDefaultBasePrices`. Otherwise `StoreInventory.ResolveBaseValue` falls back to 10 gp (weapon, shield) or 25 gp (armor).
5. Optional enum id: add `ItemID.Xxx` in `Equipment/Items/ItemID.cs` in its range (simple melee 2000-2099, martial melee 2100-2199, ranged 2200-2299, armor 3000-3299, shields 3300-3399) and map it in `ItemIdToString` (`Utilities/IdentifierExtensions.cs`). For +1/+2 variants add `{BaseEnumName}Plus1`/`Plus2` values (weapons 7000s, armor 8000-8099, shields 8100s); `ItemDatabase.RegisterEnhancedEquipmentVariants` clones bases in [2000,3400) that have them, with ids `{baseId}_plus1/_plus2`.
6. Store: `Add(ItemID.Xxx, "Mundane Weapons"|"Armor"|"Mundane Shields", priceGp)` in `StoreInventory.InitializeStore` ([Add an item to the store](#add-an-item-to-the-store)).
7. Material and masterwork variants: add the id to `ItemMaterialFactory.CommonWeaponIds / WoodenWeaponIds / CommonArmorIds / CommonShieldIds` (`Equipment/Enchantments/ItemMaterialFactory.cs`); `RegisterAllMaterialVariants` creates `mw_`, `cold_iron_`, `silver_`, `adamantine_`, `darkwood_`, `mithral_` ids. NPC spawn upgrades fall back to the plain item when a variant is missing.
8. A new `ItemData` field (as the torch commit added `NoStrengthToDamage`): declare it in `ItemData.cs`, copy it in `CloneItem` and `ItemBuilder.CopyBaseProperties`, show it in `ItemData.GetStatSummary`, consume it in `CharacterController`.
9. Distribute: class kits (`BarbarianClass.SetupStartingEquipment`: `inv.CharacterInventory.DirectEquip(ItemDatabase.CloneItem(ItemIDs.X), EquipSlot.RightHand)`) and NPC `EquipmentIds` (`new EquipmentSlotPair(ItemIDs.X, EquipSlot.RightHand)`). Test by extending a suite such as `Tests/Combat/DamageModifierTests.cs`.

Files: `Equipment/Items/ItemIDs.cs`, `ItemID.cs`, `ItemDatabase.cs`, `ItemBuilder.cs`, `ItemData.cs`, `Utilities/IdentifierExtensions.cs`, `Equipment/Enchantments/ItemMaterialFactory.cs`, `Equipment/Store/StoreInventory.cs`. Examples: 4111694, 2e8e4c0, c2dfe2c, 86d89af, 749f7e9, 525fcb8.

Pitfalls:
- `ItemDatabase.Init` sets `_initialized = true` BEFORE registering, and `ItemBuilder.Build()` throws on validation failure (missing Name, `DamageDice` 0, `CritMultiplier < 2`). One bad builder call aborts Init and every later `Get()` silently uses a partial database.
- `CloneItem` copies every public field except the 4 treasure fields; a field you forget is lost on every purchase, NPC equip and variant.
- NPC `EquipmentIds` slots: `RightHand`, `LeftHand`, `Armor`/`ArmorRobe` and the creature aliases `MainHand` (right hand), `OffHand` (left hand) and `Ranged` (ITM-004, `ItemData.ResolveHandAlias`). `Inventory.EquipStartingLoadout` equips them at spawn: a `Ranged` weapon is held only by a creature the AI runs through the ranged routine (`AIService.RoutesToRangedTurn`: `RangedKiter`, or a profile whose `CombatStyle` is Ranged, unless `DefensiveMelee`; its melee weapon goes to the pack) and carried in the pack by any other, since NPCs cannot draw a stowed weapon (ITM-069; only mindless undead re-equip, after a disarm). `DirectEquip` refuses the `Ranged` alias; `GetEquipped`, `EquipFromInventory` and `Unequip` resolve `MainHand` and `OffHand` like it does. An item that cannot go in its slot is put in the pack with a `[Inventory] DirectEquip` warning; an unknown item id is still only logged ("Item not found", CRE-052).
- `ItemDatabase.Get(string)` and `CloneItem(string)` are `[Obsolete]` (warning only). Prefer the `ItemID` overloads, use `GetItem(string)`, or wrap in `#pragma warning disable CS0618`.
- Most PHB weapons (glaive, halberd, flails) have only string ids: no store entry and no +1/+2 variants until you add the enum value and mapping.

## Add a combat scenario

A scenario is an automated Play-mode fight for the scenario harness ([TESTING.md](TESTING.md) 3.4-3.5): real turn order, AI and rules code, exact squares, seeded dice, and expectations checked against a typed trace. Use it to pin a rule, reproduce a bug, or measure AI behaviour.

1. **Pick the file.** Add a `[ScenarioSource] public static IEnumerable<ScenarioDef> All()` method (or extend one) in `Assets/Scripts/Tests/Scenarios/Catalog/<Area>Scenarios.cs`, inside `#if UNITY_EDITOR` and namespace `Tests.Scenarios`. Wrap every `yield return` in `ScenarioCatalog.Safe("<Class> <id>", () => ...)` so one invalid definition becomes a load error instead of dropping the rest.
2. **Build it.**
   ```csharp
   yield return ScenarioCatalog.Safe("RulesScenarios rules/my-rule", () =>
       Scenario.Define("rules/my-rule", "What it shows (PHB p.NNN)")
           .Tags("rules").Covers("CMB-NNN", "PHB p.NNN").MaxRounds(2)
           .Pc("hero", ActorSource.Stats(() => BuildFighter(6)), 8, 10, Control.Scripted) // your CharacterStats helper
           .Npc("orc", "orc_warrior", 9, 10, Control.Idle)
           .Initiative("orc", "hero") // the orc acts first: before its first turn it is flat-footed and makes no AoO (PHB p.137)
           .Turn("hero", 1, Step.Maneuver(SpecialAttackType.Trip, "orc")) // the trip takes the attack action's one attack (PHB p.158)
           .Force(20, 15, "Trip touch attack")
           .Expect("The trip provokes before it resolves (PHB p.158)",
               Expect.AoOBefore("orc", "hero", e => e.Ev == "maneuver"))
           .Build());
   ```
3. **Actor sources and slot limits.** `ActorSource.QuickStart(class)` (a class Quick Start character, 3rd level, through the real creation path), `ActorSource.Stats(() => stats)` (an exact `CharacterStats`; set BAB through `BaseAttackBonusOverride`, CHR-068) and NPC ids (`.Npc(key, id, x, y)`, or `.NpcPlacedByGame(key, id)` to let the game's default layout place it, as a random encounter does; confirm the id with `NPCDatabase.Get`). At most 4 party-slot actors (QuickStart and Stats, on the Player team) and 40 NPCs (`ScenarioLimits.MaxNpcActors`; the enemy pool grows past 15, ENC-001) on the 20x20 grid, one actor per square. A definition can also make actors per job with `.GenerateActors(ctx => new GeneratedActors { ... })` after the RNG is seeded (see `Catalog/SoakScenarios.cs`); use `ActorSource.Npc(id, label)` for ids registered per job, and unregister them in `Cleanup`.
4. **Choose who decides each turn.** `Control.Ai` (the game AI; a party-slot actor gets a class AI profile and takes the NPC path), `Control.Scripted` (typed steps through the same `*ForAI` executors the AI uses; `.AiWhenUnscripted(key)` hands its other rounds to the AI), `Control.Ui` (a controllable PC driven through the PC buttons and cell clicks; use it to test the PC path) or `Control.Idle` (takes no actions). Steps are `Step.Move`, `Withdraw`, `FiveFootStep`, `StandUp`, `Crawl`, `DropProne`, `Attack`, `AttackAgain`, `FullAttack`, `NaturalAttack` (Ui only), `Maneuver`, `GrappleAction`, `Cast`, `Charge`, `AnswerAoO`, `Pass`, `EndTurn`, `Assert` and `Wait`; a step the actor's path cannot run is a build error (the table in TESTING.md 3.4). Test a mechanic on both paths when PCs and NPCs share it ([systems/PC_NPC_PARITY.md](systems/PC_NPC_PARITY.md)).
5. **Pin the dice that decide the branch, nothing else.** `.Force(sides, value, ctxSubstring, count)` matches the `DiceService` context (for example "Trip touch attack"); context-free `DiceRoller` dice match by sides only, and the raw `Random.Range` sites of TST-033 cannot be forced. When a branch depends on dice you cannot pin, run a seed range or `sweep=N` and return `ExpectResult.Inconclusive(...)` from seeds where the branch did not happen; a scenario whose seeds are all Inconclusive is listed in `inconclusiveIds`.
6. **Expect structure, not golden traces.** Check events and their order with `Expect.Count`, `None`, `All`, `Any`, `AoOBefore`, `ModSequence`, `StepStatus`, `Controller`, `Outcome` or a custom `v => ...` over the `TraceView`, and put the rule cite in the expectation name. Never compare whole traces or hashes across code changes: any added or removed `Random` call shifts every later roll.
7. **Waivers and XFail need an issue ID.** `.Waive(issueId, invariant, detailRegex)` accepts a known invariant break (the job becomes Known), and `.ExpectXFail(issueId, name, check)` marks an expectation expected to fail until that issue is fixed (a pass is reported as XPASS). Never waive without a filed issue; delete the waiver or XFail when the issue is fixed (unused waivers are listed in `unusedWaivers`).
8. **Ad-hoc definitions.** For a one-off check, build the definition inline in an MCP `CommandScript` and call `ScenarioHarness.Start(def, seeds, options)`; no new file or recompile.
9. **Run it.** Compile check, `AssetDatabase.Refresh()` in edit mode, a fresh Play session, `ScenarioHarness.Start("rules/my-rule", "1-5")`, then poll `Logs/Scenarios/<runId>/status.json` and read `summary.json` and the per-job JSONL traces next to it. Or from edit mode, `ScenarioHarness.QueueFresh("rules/my-rule,soak/*", "1-5", "")` runs each filter in its own fresh session and writes `Logs/Scenarios/batch.json`. Add the new scenario to the rules table in TESTING.md 3.4.

Pitfalls:
- Never run scenarios in a Play session that ran static suites (the harness answers `needsFresh`), and never edit scripts or call `AssetDatabase.Refresh` while a run is going.
- Every combatant is flat-footed until its first turn (PHB p.137, CMB-028): it has no Dexterity bonus to AC and makes no AoO (unless it has Combat Reflexes). A watcher that must take an AoO in round 1 needs an earlier initiative count than the provoker; an AC check in round 1 sees the target without its Dexterity bonus unless it has acted or has uncanny dodge.
- A scripted actor bypasses the AI's automatic stand-up and grapple turn; a grappling scripted actor cannot move or make ordinary attacks.
- Prompts other than the AoO confirmation, the counter-trip prompt and the touch-spell prompt (answered Cast Now by the Ui `Cast` step) soft-lock a Ui actor: bull rush push and follow, Improved Grab, the disarm item choice.
- `ScenarioHooks` must stay null outside the harness, and rules code must never read it.

If it provokes an AoO: add a value to `AoOProvokingAction` (`Combat/Core/AoOProvokingAction.cs`) and call `ShowAoOActionConfirmation` (`GameManager.cs:11434`) with an `AoOProvokingActionInfo { ActionType, ActionName, ActionDescription, Actor, ThreateningEnemies, OnProceed, OnCancel }` (examples: DrinkPotion `GameManager.cs:4517-4523`, Movement `GameManager.CombatActions.cs:696-702`). If the action moves the actor, compute the path's AoOs with `CheckForAoO`/`ThreatSystem.AnalyzePathForAoOs` and resolve them with `ResolveMovementAoOsBeforeStep` before each step: that helper also records each opponent's movement opportunity for the round, so a second move that round does not provoke the same opponent again (PHB p.138, CMB-128). A mover that resolves its own steps must call `ThreatSystem.RecordMovementOpportunity` itself, as the bull rush follow does. The overrun move (`GameManager.RunOverrunMove`) resolves and records its movement AoOs through `ResolveMovementAoOsBeforeStep`. The grapple moves pass the creatures in the same grapple as `AnalyzePathForAoOs(..., excludedThreateners:)` (CMB-152); pass any creature that must not get an AoO from this move the same way. Filter provokers with `ThreatSystem.CanMakeAoOAgainst(threatener, provoker)`, not `CanMakeAoO` alone: it also drops an Improved Grab holder against the creature it holds (CMB-163). A new attack entry (button, click, AI branch) asks the one direct-attack gate before any cost, `AttackLegality.CanDirectlyAttack(attacker, target, kind, intent)` (`Combat/Core/AttackLegality.cs`; or `AttackLegality.Check` without a test the entry already makes, such as its own reach): the Improved Grab hold bar, the Resilient Sphere, reach and range by kind and a known failed Sanctuary or Hide from Undead save, pure. When the attack is then attempted (after its cost, before its roll), call `AttackLegality.CommitWard(attacker, target, kind, intent)`: on `WardVerdict.Failed` the step or action stays spent and the attack stops (the ledger logs it; a spell keeps its slot, which the cast core's Ward stage does for you). A target picker or AI score only predicts (`WardSaveLedger.Predict`, `AttackLegality.WardTargetScoreAdjustment`) and never rolls.
6. Target selection: follow the special-attack flow (`CurrentSubPhase` or a pending-mode field, highlights, `HandleXTargetClick`; `GameManager.CombatActions.cs:1385-1514`).
7. In Play mode check visibility on the PC turn, the NPC turn and while grappling.

Files: `UI/Combat/CombatUI.cs`, `_Core/SceneBootstrap.cs`, `UI/Combat/ActionButtonPanel.cs`, `_Core/GameManager.cs`, `Combat/Core/AoOProvokingAction.cs`. Examples: 897d2f4, 44eb44e, a44274b, f632d63.

Pitfalls:
- A field that SceneBootstrap never creates stays null and every null-guarded path skips it silently: `StunningFistPanel`/`ManyshotPanel` (65be722), `BardicMusicStatusText` (897d2f4), `DualWieldButton`, `FullAttackDefensivelyButton`. Create it in SceneBootstrap or clone it at runtime (as CombatUI does for `DischargeTouchButton`).
- `ActionButtonPanel.ApplyButtonStates` only touches buttons that got a `Set()` this refresh; others keep their previous state.
- Without the Hide* entries the button stays visible during grapples and NPC turns.
- Derive state from `CharacterStats`/`ActionEconomy` on each refresh (`ActionButtonPanel.UpdateActionButtons` via `CombatUI.UpdateActionButtons`), not from cached button state.

## Add a UI panel

1. Put the MonoBehaviour in `UI/Combat`, `UI/Encounter`, `UI/Inventory`, `UI/Spells`, `UI/Crafting`, `UI/CharacterSheet`, `UI/CharacterCreation`, `UI/Wish` or `UI/Common`. `UI/Panels` is an empty leftover.
2. Pattern A, always-present modal (combat panels): `public void BuildUI(Canvas canvas)` builds a full-screen dark overlay `Image` (anchors 0..1) with a centered root and ends with the overlay inactive. Expose `Open(...)`, `Close()`, `public bool IsOpen { get; private set; }` and `Action` callbacks (pattern `UI/Combat/QuickItemUsePanel.cs`). Add a public field on GameManager (e.g. `QuickItemUsePanel`, `GameManager.cs:84`) and in `SceneBootstrap.SetupGameManager` (`:997+`): `var x = canvas.gameObject.AddComponent<X>(); x.BuildUI(canvas); gm.X = x;` (examples `:1032-1054`). If a combat button opens it, follow [Add a combat action button](#add-a-combat-action-button) with a handler like `OnUseItemButtonPressed` (`GameManager.cs:4613-4657`); a44274b shows every touch point.
3. Pattern B, on-demand full-screen panel: the owner creates it lazily with two explicit null checks (`if (x == null) x = FindObjectOfType<X>(); if (x == null) x = gameObject.AddComponent<X>();`, `GameManager.OpenCraftingWorkshopFromPreCombat`), and the panel builds itself in a private `EnsureBuilt()` on first `Open`, finding the canvas with `GetComponentInParent<Canvas>()` then `FindObjectOfType<Canvas>()` (`CustomEncounterBuilderUI.cs:113-118`).
4. Pre-combat hub button: add an optional `Action` parameter at the end of `PreCombatHubUI.Open` (`UI/Encounter/PreCombatHubUI.cs:38-61`), a `CreateButton(...)` row (`:148-156`; `firstButtonY = 180`, step 94), pass the callback from `GameManager.OpenPreCombatHubPhase`, call `PreCombatHubUI?.HideMenu()` before opening, and pass `onClose: () => ReturnToPreCombatHubFromSubWindow("X.Back")` (6931142 added the Crafting Workshop this way).
5. Helpers: prefer `UIFactory` (`UI/Common/UIFactory.cs`: `GetDefaultFont`, `CreateButton`, `CreateLabel`, `CreatePanel`, `CreateScrollPanel`, `CreateInputField`, layouts) and `UITheme` over the private `MakePanel/MakeText` copies in older panels.
6. Call `SetAsLastSibling()` on open. Keep a raycast-target `Image` on the overlay: `InputService.BuildClickContext` drops grid clicks only when the pointer is over UI. Modals during the player's turn also add an `X != null && X.IsOpen` check to `GameManager.CanProcessWorldInput` (`GameManager.cs:2318-2342`).
7. Hotkey debug panels are attached in `CreateUI` and poll `Input.GetKeyDown` themselves (`SpellTestingPanel`, F12). `activeInputHandler: 2` enables both input systems.
8. Check the layout in Play mode at 1920x1080 and at a smaller window.

Files: `UI/<Area>/<NewPanel>.cs`, `_Core/SceneBootstrap.cs`, `_Core/GameManager.cs`, `UI/Encounter/PreCombatHubUI.cs`, `UI/Common/UIFactory.cs`, `UI/Common/UITheme.cs`, `Services/InputService.cs`. Examples: a44274b, fdd49c9, 140de6f, 6931142, cb05db7, 936bbc1, 516dbff, 4798c86, f632d63.

Pitfalls:
- Fonts: load `Resources.GetBuiltinResource<Font>("LegacyRuntime.ttf")` first; `Arial.ttf` is no longer built in (4798c86). Use `UIFactory.GetDefaultFont`; do not copy `SpellStorageUI.cs:145/166/182`.
- Do not use `??` or `?.` on `UnityEngine.Object` for create-if-missing: they bypass Unity's `== null`, so a destroyed component counts as present. Some existing code still does `GetComponent<X>() ?? AddComponent<X>()`.
- A Pattern A panel never assigned to its GameManager field fails only at runtime ("panel is not available").
- The pre-combat hub uses fixed pixel offsets for six buttons; a seventh may overflow. Layout regressions were the most common UI follow-up fix (790b5d1, 6f65a92, ef0ec6e, 382d47e, fafa38e, 2a9f6d1, f632d63, b0e35ac); anchor-based layouts held up better.
- `InputService.HandleKeyboardInput` runs before the `CanProcessWorldInput` gate, so a modal does not block hotkeys unless the handler checks for it.
