# Known issues: UI (UI-)

## Bugs and rules deviations

- **UI-001** · **High** · Player-visible — **Combat log rebuilds its message pool on every log call.** `CombatUI.EnsureCombatLogPanel` calls `CombatLogPanel.Initialize` each time, which builds a new `ObjectPool<Text>` prewarmed with 50 objects, so each log line orphans about 50 inactive "PooledLogMsg" GameObjects at the scene root. Observed in Play mode on 2026-10-07: one `FlankingReachRulesTests` run created 588 of them, and about 1,800 had piled up after three filtered runs before the static-suite runner started destroying them (docs/TESTING.md 3). In a Play session of about 60 scenario-harness fights on 2026-10-07 the scene reached 52,931 of them and the frame rate fell from about 70 to about 9 frames per second (docs/TESTING.md 3.4). *Evidence:* Assets/Scripts/UI/Combat/CombatUI.cs:656-665; Assets/Scripts/UI/Combat/CombatLogPanel.cs:34-89. *Fix:* build the pool only when `_logMessagePool == null`.
- **UI-002** · **Med** · Player-visible — **Camera can drift back from the grid centre at startup.** If `CameraController.Start` runs before `GameManager.CenterCamera` (Start order is not guaranteed), it keeps the scene position (8, 7, -10) as its pan target and `ApplyPan` lerps back there every frame (not verified in Play mode); `SquareGrid.GetGridCenter` also returns (10, 10), not (9.5, 9.5). *Evidence:* Assets/Scripts/Utilities/CameraController.cs:60-76, 446-453; Assets/Scripts/_Core/GameManager.cs:3615-3624. *Fix:* have `CenterCamera` call `cameraController.CenterOnPosition` and use `(Width - 1) / 2f` for the centre.
- **UI-003** · **Med** · Player-visible — **Bard spells known at creation do not follow PHB Table 3-5.** `SpellSelectionUI.OpenForSorcerer(level, "Bard")` uses its own table (L1 4/1 vs RAW 4/0, L3 5/3 vs 6/3, L4 5/3/1 vs 6/3/2), so a level-1 bard picks a 1st-level spell it has no slots for; the comments in SpellSelectionUI and CharacterCreationUI are wrong too. *Evidence:* Assets/Scripts/UI/Spells/SpellSelectionUI.cs:364-388; Assets/Scripts/Spell/Data/SpontaneousCastingData.cs:378-427. *Fix:* take the limits from `SpontaneousCastingData.GetMaxSpellsKnown` and fix the comments.
- **UI-004** · **Low** · Player-visible — **Inventory changes refresh only PC1, PC2 and first-NPC stat panels.** `InventoryUI.NotifyStatsChanged` calls the legacy `CombatUI.UpdateAllStats(PC1, PC2, NPC)`, so it does not refresh PC3 or PC4 (whether another refresh covers them is not verified in Play mode). *Evidence:* Assets/Scripts/UI/Inventory/InventoryUI.cs:861-867; Assets/Scripts/_Core/GameManager.cs:2982-3002. *Fix:* use the 4-PC refresh (`GameManager.UpdateAllStatsUI`, now private), then retire `GameManager.NPC`.
- **UI-005** · **Low** · Player-visible — **Kobold sorcerers get the orc token.** `IconLoader.DetermineMonsterType` matches keywords as substrings of the NPC name, so "orc" matches "sorcerer" (CSV-spawned names get the class appended). Only 5 monster types have token sprites; the rest get a tinted generic sprite. *Evidence:* Assets/Scripts/UI/Common/IconLoader.cs:121-135; Assets/Scripts/Encounters/DungeonEncounterSpawner.cs:171. *Fix:* match whole words or add a token key to `NPCDefinition`.
- **UI-006** · **Low** · Player-visible — **"Reset UI" does not reset the pre-combat inventory window.** `CombatUI.ResetFloatingWindowLayout` clears and restores the combat log and action panel rects but not `ui_window_precombat_inventory`, the third persisted window. *Evidence:* Assets/Scripts/UI/Combat/CombatUI.cs:449-485; Assets/Scripts/UI/Inventory/PreCombatInventoryUI.cs:705. *Fix:* also call `DeleteWindowPrefs("ui_window_precombat_inventory")` and reapply its default rect.

- **UI-011** · **Low** — **F12 spell testing panel stats bar always shows zeros.** Its counters are written only by `TrackDamage`, `TrackSave` and `TrackSR`, and nothing calls them (or `LogMessage`); debug tool only. *Evidence:* Assets/Scripts/UI/Spells/SpellTestingPanel.cs:27-32, 1229-1275. *Fix:* call the Track* methods from the GameManager.TestPanel spell resolution, or delete the bar, the four methods and the unused `using System.Reflection;`.

## Development traps

- **UI-012** · **Med** — **`GameManager.ShowActionChoices` cancels active targeting.** It resets `CurrentSubPhase` to `ChoosingAction`, so a UI callback that calls it during a targeting pipeline cancels that targeting. The Quick Use Item callback skips it while a scroll or wand cast is pending; new UI callbacks need the same guard. *Evidence:* Assets/Scripts/_Core/GameManager.cs:4143, 4643-4647. *Fix:* put an `IsTargetingPipelineActive` check inside `ShowActionChoices`, or in a wrapper used by all UI callbacks.
- **UI-013** · **Med** — **Unassigned CombatUI fields fail silently.** Every use of a CombatUI field is null-guarded, so a field SceneBootstrap does not assign disables its feature with no error. Never assigned today: the Stunning Fist and Manyshot fields, `DualWieldButton`, `FullAttackDefensivelyButton`, `BardicMusicStatusText` and `CombatLogText` (see CMB-022, UI-007, UI-045). *Evidence:* Assets/Scripts/UI/Combat/CombatUI.cs:86, 122, 135, 158, 161-166. *Fix:* create and assign every new CombatUI field in SceneBootstrap in the same change; wire or remove the unassigned ones.
- **UI-014** · **Med** · Player-visible — **Debug tooling ships ungated in release builds.** `SceneBootstrap` always adds `SpellTestingPanel` (F12) with no `Debug.isDebugBuild`, `DEVELOPMENT_BUILD` or `UNITY_EDITOR` guard, so any player can open it; UI code also has about 520 ungated `Debug.Log*` calls, and the Left Ctrl+H HP-mode hotkey is ungated too (CORE-007). *Evidence:* Assets/Scripts/_Core/SceneBootstrap.cs:192-193; Assets/Scripts/UI/Spells/SpellTestingPanel.cs:94. *Fix:* wrap the `AddComponent` in `if (Debug.isDebugBuild)` and route UI logging through a gated logger.
- **UI-015** · **Low** — **Database initialization is interleaved with UI construction.** SceneBootstrap runs the database `Init` and `Register*InItemDatabase` calls between panel builds. Most databases initialize lazily, but `CraftableItemRegistry` getters never call `Init` and the `Register*` calls are explicit, so moving a panel above them can produce empty lists. *Evidence:* Assets/Scripts/_Core/SceneBootstrap.cs:1036-1080; Assets/Scripts/Crafting/CraftableItemRegistry.cs:61-72. *Fix:* move all database Init/Register calls into one block at the top of `SceneBootstrap.Awake`.
- **UI-016** · **Low** · Player-visible — **Hotkeys and Esc have no input focus model.** `I` does nothing because InventoryUI is embedded in the character sheet and `HandleInventoryInput` returns early; Esc is polled independently by InputService, CraftingWorkshopUI, LootCollectionUI and CombatUI with no modal stack, so one press can trigger several handlers. *Evidence:* Assets/Scripts/_Core/GameManager.cs:2511-2513; Assets/Scripts/Services/InputService.cs:350, 356. *Fix:* add a modal/input-focus stack so the topmost panel consumes Esc; remove `I` or make it open the inventory tab.
- **UI-017** · **Low** — **`SpellPreparationUI.DoesPrepareSpells` disagrees with SpellcastingComponent.** It counts Bard, Paladin and Ranger as prepared casters (a 3.5e Bard is spontaneous); single-class ones are skipped only because `SpellcastingComponent` fills `SpellSlots` for Wizard, Cleric and Druid alone. *Evidence:* Assets/Scripts/UI/Spells/SpellPreparationUI.cs:281-311; Assets/Scripts/Spell/Components/SpellcastingComponent.cs:160-172. *Fix:* derive it from `SpellcastingComponent.GetPreparedCasterClassNames()`.
- **UI-018** · **Low** — **F12 test panel needs a PC's turn and temporarily rewrites the caster.** `SpellTestingPanel.CastSpell` requires `gm.ActivePC` (non-null only in `TurnPhase.PCTurn`); for a non-caster it adds a temporary Wizard 10 entry and SpellcastingComponent, may boost an ability score, and restores them from `Update` polling. *Evidence:* Assets/Scripts/UI/Spells/SpellTestingPanel.cs:99-110, 1006-1090; Assets/Scripts/_Core/GameManager.TestPanel.cs:62-64. *Fix:* also verify spell changes from a normal PC turn, and do not test class-dependent behavior on a temporary caster.
- **UI-019** · **Low** — **Absolutely positioned scroll content leaves blank space at the top.** Content RectTransforms use pivot (0.5, 1), but children anchored at (0.5, 0.5) are placed relative to the content centre; CharacterCreationUI works around it with `yOffset = contentH / 2`. *Evidence:* Assets/Scripts/UI/CharacterCreation/CharacterCreationUI.cs:731-746. *Fix:* anchor list children at (0.5, 1), or use VerticalLayoutGroup + ContentSizeFitter.
- **UI-020** · **Low** — **UGUI layout pitfalls seen in past fixes.** (1) `UIFactory.CreateScrollPanel` adds no LayoutElement, so inside a LayoutGroup it needs explicit heights; (2) a fully transparent mask did not clip (SpellTestingPanel uses alpha 0.004, `CreateScrollPanel` still 0); (3) overlapping Text with `raycastTarget = true` blocks clicks; (4) sibling order is draw order. *Evidence:* Assets/Scripts/UI/Common/UIFactory.cs:292-345; Assets/Scripts/UI/Spells/SpellTestingPanel.cs:338. *Fix:* fold these into UIFactory (default LayoutElement, 0.004 alpha or RectMask2D, `raycastTarget = false` on labels).
- **UI-021** · **Low** — **The spell testing panel bypasses the turn guards.** GameManager.TestPanel.cs forces `CurrentPhase = TurnPhase.PCTurn` and skips the ActivePC/turn-phase guards for SpellTestingPanel casts, so a cast that works there has not exercised the normal PC-turn path. *Evidence:* Assets/Scripts/_Core/GameManager.TestPanel.cs:35-36, 59-64. *Fix:* also verify spell changes from a normal PC turn.

## Performance

- **UI-022** · **Low** — **Diagnostic logging and per-frame rebuilds in combat UI.** `LogSpecialStyleMenuLifecycle` logs a stack trace per menu event, `ShowPickUpItemSelection` dumps the full UI hierarchy on every open, `StatusEffectIndicator` rebuilds its data every LateUpdate, and `CombatLogPanel.AddMessage` starts a `ForceUpdateCanvases` coroutine per message (not profiled; see also UI-001). *Evidence:* Assets/Scripts/UI/Combat/CombatUI.cs:504-508, 4073-4307; Assets/Scripts/UI/Combat/StatusEffectIndicator.cs:57-74. *Fix:* gate diagnostics behind a debug flag, rebuild indicator data on condition changes, and coalesce scroll-to-bottom.
