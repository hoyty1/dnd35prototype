# Known issues: Encounters (ENC-)

## Bugs and rules deviations

- **ENC-002** · **Med** · Player-visible — **Many DMG dungeon-table rows spawn nothing or only part of the group.** `DungeonEncounterTableData.ResolveCreatureName` falls back to plurals ("stirges") or bare NPC races ("human") that `NPCDatabase.Get` misses, so `DungeonEncounterSpawner.PrepareEncounter` skips them (if all fail, the selection panel reopens). A static count (not re-run) found 30 of 238 non-cascade rows unresolved and 6 partial. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableData.cs:313-358; Assets/Scripts/Encounters/DungeonEncounterSpawner.cs:98-107. *Fix:* Resolve via `Depluralize` plus NPCDatabase validation, and map NPC races to NPC IDs.
- **ENC-003** · **Med** · Player-visible — **The CSV name map sends several creatures to the wrong variant.** Stale plural keys in `DungeonEncounterTableManager.InitializeTypoCorrections`, checked before singular forms, map e.g. "Medium/Large monstrous spiders" to `*_small` and "troglodyte zombies" to `zombie_shambler` (and 3 more), though the right IDs exist. All occur in dungeon_encounters.csv, so those rolls spawn weaker or wrong creatures. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:696, 701, 806-815. *Fix:* Point them at `monstrous_*_medium/_large`, `zombie_troglodyte` and `skeleton_human_warrior`, and delete the stale comments.
- **ENC-004** · **Med** · Player-visible — **Temporary `spawn_*` NPC definitions leak for the whole session.** The live DMG-table path (`EncounterSelectionUI.OnDMGTablesPressed`) registers each creature via `NPCDatabase.RegisterExternal` but never calls `DungeonEncounterSpawner.CleanupSpawnEntries`. They then appear in the Custom Encounter Builder and become `RandomEncounterSystem` candidates. *Evidence:* Assets/Scripts/UI/Encounter/EncounterSelectionUI.cs:653-692; Assets/Scripts/Encounters/DungeonEncounterSpawner.cs:109-128, 548-561; Assets/Scripts/UI/Encounter/CustomEncounterBuilderUI.cs:358-389. *Fix:* Call `CleanupSpawnEntries` after combat and exclude "spawn_" in both list builders.
- **ENC-023** · **Low** · Player-visible — **Only the first three enemies get a stat panel.** `SceneBootstrap.CreateUI` builds 3 NPC panels (`CreateNPCPanelsRight(..., 3)`), and `GameManager.SetupEnemyEncounter` fills a panel only for indices below `CombatUI.NPCPanels.Count`, so the 4th and later enemy's stats show only in the hover tooltip. Split from ENC-001 (fixed 2026-10-08: every enemy now spawns on the grid and the pool grows past 15); not verified in Play mode. *Evidence:* Assets/Scripts/_Core/SceneBootstrap.cs:174; Assets/Scripts/_Core/GameManager.NPCSetup.cs (`SetupEnemyEncounter`, `i < CombatUI.NPCPanels.Count`). *Fix:* a scrollable or paged enemy panel list sized to the encounter, or a compact roster.
- **ENC-020** · **Low** · Player-visible — **SummonBase tag excludes 43 real creatures from CR/EL random encounters.** RandomEncounterSystem.BuildCandidates drops every NPC tagged SummonBase, SummonAlias or Summoned, which removes real MM creatures added for summon lists (ape, black bear, hell hound, elementals, mephits and others) from CR/EL-generated encounters. Owned by CREATURES.md section 1. *Evidence:* Assets/Scripts/Encounters/RandomEncounterSystem.cs:341, 376-382; Assets/Scripts/Character/Creatures/NPCDatabase_*.cs ("SummonBase" tags). *Fix:* Exclude only SummonAlias/Summoned entries (or a dedicated alias flag) and keep SummonBase creatures in the random pool.
- **ENC-022** · **Low** — **The encounter parser never detects creature templates such as fiendish or celestial.** `EncounterDescriptionParser` fills `ParsedCreatureGroup.TemplateIds` only for the half-dragon row, although the field's comment names fiendish and celestial and `DungeonEncounterSpawner` applies parsed templates. The one CSV row with a template prefix, "1d4+1 fiendish dire rats" (level 2), spawns only because `DungeonEncounterTableManager` maps "fiendish dire rat" to the hand-made `fiendish_dire_rat` NPC, not to the dire rat with the fiendish template. Phase5IntegrationTests fails "Fiendish template detected" (2026-10-07). *Evidence:* Assets/Scripts/Encounters/EncounterDescriptionParser.cs:44-48, 460; Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:661; Assets/StreamingAssets/dungeon_encounters.csv:30; Assets/Scripts/Tests/Encounters/Phase5IntegrationTests.cs ("Fiendish template detected"). *Fix:* parse template prefixes into `TemplateIds` and spawn the base creature with the template, or record the dedicated entry as the design and update the test.

## Unreachable or stubbed features

- **ENC-005** · **Med** · Player-visible — **Dominated, companion and half-dragon CSV annotations are dropped.** "dominated" and "(with X)" go into `ParsedCreatureGroup.Notes`, which nothing reads, so dominated NPCs spawn as enemies and companions never spawn. `CreatureTemplateRegistry` has no "half-dragon" template and `ResolveTemplates` skips it silently, so the one half-dragon row (level 6, d% 53-54, "1 half-dragon 4th-level fighter") would spawn a plain NPC; today it spawns nothing, because its race resolves to `human`, which has no NPC ID (ENC-002). *Evidence:* Assets/Scripts/Encounters/EncounterDescriptionParser.cs:411, 436, 460; Assets/Scripts/Character/Templates/CreatureTemplateFramework.cs:30-62; Assets/StreamingAssets/dungeon_encounters.csv:166. *Fix:* Spawn companions, make dominated NPCs allies or neutral, and add the template or warn on unknown IDs.
- **ENC-006** · **Low** — **Dungeon-table Encounter Level and party level are placeholders.** `DungeonEncounterTableData.EstimateEL` always returns the dungeon level (no CR lookup), and the `partyLevel` argument of `DungeonEncounterTableManager.GenerateRandomEncounter` only appears in a log line. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableData.cs:200, 371-383; Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:339-352. *Fix:* Compute EL from the creatures' CRs and decide whether party level should affect generation.
- **ENC-021** · **Med** · Player-visible — **DMG class-levelled casters get caster AI but no spells.** `DungeonEncounterSpawner.UpdateAIForClass` gives Wizard, Sorcerer, Cleric, Druid, Bard and Adept spawns RangedKiter plus a caster profile, but neither it nor `CreatureClassEngine.ApplyClassToDefinition` fills `KnownSpellIds`/`PreparedSpellSlotIds`. Without them `InitializeNPCFromDefinition` adds no `SpellcastingComponent`, so these spawns hang back and never cast. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterSpawner.cs:168, 224-260; Assets/Scripts/Character/CreatureClass/CreatureClassEngine.cs:140; Assets/Scripts/_Core/GameManager.NPCSetup.cs:948-950. *Fix:* Generate class spell lists (or auto-prepare from the class list) when a caster class is applied to a definition.

## Development traps

- **ENC-007** · **Med** · Player-visible — **Dungeon tables stop at level 8; tests and the parser disagree.** `MaxLevel` and the CSV stop at 8, yet Phase5IntegrationTests asserts 9 (failing) and `EncounterCSVParser` accepts 1-20. `DungeonEncounterTable.Validate` logs level 1's missing "roll easier" row every load, and the level-8 91-100 row re-rolls level 8 until `MaxCascadeDepth` (3), then takes the first non-cascade entry. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:57, 415-450; Assets/Scripts/Tests/Encounters/Phase5IntegrationTests.cs:137-155, 406-439. *Fix:* Set the tests to 8 (or restore 9), relax the level-1 check, and drive the UI from `EffectiveMaxLevel`.
- **ENC-008** · **Low** — **The dungeon CSV loads only on desktop.** `DungeonEncounterTableManager` reads StreamingAssets/dungeon_encounters.csv with `File.Exists`/`File.ReadAllLines`, which fails on Android and WebGL, so the hard-coded fallback tables (different counts, d% ranges and cascades) load after only a `Debug.Log`. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:115-117, 142-152; Assets/Scripts/Encounters/EncounterCSVParser.cs:73-82. *Fix:* Load through `UnityWebRequest`, or ship the CSV as a TextAsset in Resources.
- **ENC-009** · **Low** — **Unknown creature names pass the CSV load without an error.** Both `ResolveCreatureName` functions return null only for empty input, so the "N unresolved creature names" log is always 0 and bad names surface only as spawn-time warnings. The ~245-assignment map in `InitializeTypoCorrections` is never validated and has duplicate keys (the later value silently wins). *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableData.cs:250-277, 313-345; Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:506-817 (the map; duplicates e.g. 592/671), 824-845 (its `ResolveCreatureName`). *Fix:* Return null for IDs not in NPCDatabase, and move the map to a data file that rejects duplicate keys.
- **ENC-010** · **Low** — **`DungeonEncounterTableManager.IsCSVLoaded` can be true when the CSV was not used.** On 0 parsed rows `BuildFromCSV` returns the hard-coded tables, which `LoadTables` counts as a CSV load; the flag only feeds logs and debug/test output. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableData.cs:72-77; Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:121-126, 155. *Fix:* Return an empty dictionary on 0 rows and let `LoadTables` do the fallback.
- **ENC-011** · **Low** — **`DungeonEncounterTableManager.RunIntegrationTest` passes any non-null encounter.** It never checks that `BaseCreatureIds` exist in NPCDatabase or that `PrepareEncounter` succeeds. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:928-942; Assets/Scripts/Tests/Encounters/Phase5IntegrationTests.cs:186. *Fix:* Also run `PrepareEncounter` (or `NPCDatabase.Get` per entry) and count unresolved IDs as failures.
- **ENC-012** · **Low** — **An unknown encounter preset ID silently loads the first preset.** `NPCDatabase.GetEncounterPreset` falls back to the first preset without a warning, and `GameManager.ApplyEncounterPreset` sets the test flags from the raw ID, so a typo loads the wrong enemies with every test flag off. *Evidence:* Assets/Scripts/Character/Creatures/NPCDatabase.cs:168-176; Assets/Scripts/_Core/GameManager.cs:1769-1790. *Fix:* Log a warning and return null, or make the fallback explicit.
