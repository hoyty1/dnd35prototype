# Known issues: Tests (TST-)

## Bugs and rules deviations

- **TST-001** · **Med** — **CharmPersonRulesTests reflects on `GetSaveModifier` with 6 of its 8 arguments.** `InvokeGetSaveModifier` passes 6 arguments but the private `SpellCaster.GetSaveModifier` takes 8 (two `out` situational-save parameters were added), so `MethodInfo.Invoke` throws `TargetParameterCountException`, which escapes `CharmPersonRulesTests.RunAll` (try/finally only) before its results line. *Evidence:* Assets/Scripts/Tests/Combat/CharmPersonRulesTests.cs:129-164, 166-196; Assets/Scripts/Spell/Casting/SpellCaster.cs:971-979. *Fix:* Pass 8 arguments `{ stats, spell, default, caster, target, 0, 0, null }`, or make the method `internal` and call it directly.

## Unreachable or stubbed features

- **TST-002** · **Med** — **Nothing runs the test suites; no evidence they ever ran in Unity.** The 98 static entry points (95 `RunAll()`, 3 `RunAllTests()`) use no test framework; the only runner, `ServiceTestRunner.RunAll` (9 of 13 Services suites), is never called, and the three MonoBehaviour suites are attached to nothing. Wrong assertions go unnoticed (ENC-007, CHR-009, CHR-013) and the real spawn path (`SetupEnemyEncounter`) is untested. *Evidence:* Assets/Scripts/Tests/Services/ServiceTestRunner.cs:23-46; Assets/Scripts/Tests/Combat/FlankingReachRulesTests.cs:10-14. *Fix:* Add an editor `MenuItem` that runs every suite in try/catch and logs totals, then run it once in Play mode.
- **TST-003** · **Med** — **38 placeholder `Assert(true, ...)` calls count as passes.** TeamUtilityTests is all stubs (10), SpellTargetingServiceTests has 9 and 9 other suites have 19; many "needs mock" reasons are outdated now that `TestHelpers.CreateCharacter` builds real controllers, and the two EconomyServiceTests stubs are unreachable because `ItemDatabase.Get` always registers longsword. *Evidence:* `grep -rnE 'Assert[A-Za-z]*\(\s*true\s*,' Assets/Scripts/Tests`; Assets/Scripts/Tests/Services/EconomyServiceTests.cs:200-204; Assets/Scripts/Tests/Utilities/TestHelpers.cs:57-91. *Fix:* Count skips separately and implement the mock-dependent tests with `TestHelpers.CreateCharacter`.
- **TST-004** · **Low** — **Power Word Stun check cannot fail; its production hook is unreachable.** No spell with id `power_word_stun` exists, so `CoreConditionRulesTests.TestSpellConditionMappingsPresent` always takes its INFO-log branch, and the Stunned mapping that checks `spell.SpellId == "power_word_stun"` never matches. *Evidence:* Assets/Scripts/Tests/Combat/CoreConditionRulesTests.cs:306-310; Assets/Scripts/Spell/Resolution/GameManager.SpellCasting.cs:6720. *Fix:* Add Power Word Stun to SpellDatabase and assert on it, or delete the hook and the soft check.
- **TST-005** · **Low** — **DispelMagicRulesTests pass vacuously without a GameManager.** With `GameManager.Instance` null, the targeted-dispel fallback reimplements the loop and force-removes `ActiveEffects[0]` on a failed roll, so "removes at most 1" passes regardless of `PerformTargetedDispel`; the empty-target and area tests skip the dispel call entirely. *Evidence:* Assets/Scripts/Tests/Combat/DispelMagicRulesTests.cs:244-276, 362-366, 391-395. *Fix:* Fail, or report an explicit SKIP, when no GameManager exists.

## Development traps

- **TST-006** · **Med** — **String-based reflection on private members breaks only at runtime.** 16 suites make about 48 `GetMethod`/`GetField`/`GetProperty` calls (plus 3 `GetNestedType`), none using `nameof`, mostly on GameManager (`_conditionService`, `_activeSummons`, `_mirrorImageStates` and about 24 more) plus CharacterController and `SpellCaster.GetSaveModifier` (TST-001); moving summons into SummoningService would silently break MagicCircleRulesTests and ProtectionFromAlignmentTests. *Evidence:* `grep -rnE '\.Get(Field|Method|Property|NestedType)\(' Assets/Scripts/Tests`; Assets/Scripts/Tests/Combat/MagicCircleRulesTests.cs:653, 664. *Fix:* Make these members `internal` and call them directly; grep Tests/ after renaming a private member.
- **TST-007** · **Med** — **Suites that create a GameManager behave differently per loaded scene.** In the 14 suites that `AddComponent<GameManager>()`, a scene GameManager makes `Awake` destroy the new one before creating services (hence the reflection-injected `_conditionService`); otherwise it becomes `GameManager.Instance`. `OnDestroy` never clears `Instance`, leaving a destroyed object that Unity's `==` treats as null but `?.` does not. *Evidence:* Assets/Scripts/_Core/GameManager.cs:27, 483-490, 578; Assets/Scripts/Tests/Combat/SleepSpellRulesTests.cs:161, 232. *Fix:* Clear `Instance` in `OnDestroy` when it is `this`, and run suites consistently with or without the scene GameManager.
- **TST-008** · **Low** — **Stale class tests would fail (class count, Adept IDs, ECL).** `Phase3ClassTests.TestAllElevenClassesRegistered` expects 11 classes but `ClassRegistry.Init` registers 16 (11 PHB, 5 NPC), `TestAdeptSpellLookup` queries uppercase IDs against the lowercase, case-sensitive `AdeptSpellList`, and `TestCharacterStatsECL` asserts `warrior.ECL != null`, which nothing assigns. *Evidence:* Assets/Scripts/Tests/Classes/Phase3ClassTests.cs:616; Assets/Scripts/Tests/Classes/NPCTemplateSystemTests.cs:341-345, 865-875; Assets/Scripts/Character/Classes/NPC/AdeptSpellList.cs:38-47. *Fix:* Assert 16 (or PHB only), use lowercase IDs, and fix the ECL assertion with CHR-028.
- **TST-009** · **Low** — **Some suites work only in Play mode.** The `AreaEffectManager.Instance` getter creates a GameObject and calls `DontDestroyOnLoad`, which Unity rejects outside Play mode (ConcealmentRulesTests uses it), and suites that `AddComponent<GameManager>` depend on `Awake` running. *Evidence:* Assets/Scripts/Spell/AreaEffects/AreaEffectManager.cs:13-25; Assets/Scripts/Tests/Combat/ConcealmentRulesTests.cs:210, 244. *Fix:* Run suites from a Play-mode hook, or guard `DontDestroyOnLoad` with `Application.isPlaying`.
- **TST-010** · **Low** — **Tests reseed the global RNG and never restore it.** 12 `Random.InitState(seed)` calls in 6 files change the shared `UnityEngine.Random` state, and `DiceService` calls `Random.Range` with no seed or injection API, so later game rolls in the same session become deterministic. *Evidence:* Assets/Scripts/Tests/Combat/CoreConditionRulesTests.cs:133, 172, 274; Assets/Scripts/Tests/Combat/ConcealmentRulesTests.cs:278; Assets/Scripts/Services/DiceService.cs:29-40. *Fix:* Save `Random.state` before seeding and restore it in `finally`, and add `DiceService.SetSeed` or an injectable roll provider.
- **TST-011** · **Low** — **Namespace `Tests.Inventory` shadows the global `Inventory` class.** Inside every `Tests.*` namespace, test code must write `global::Inventory`. *Evidence:* Assets/Scripts/Tests/Inventory/PostCombatLootCollectionTests.cs:7; Assets/Scripts/Tests/Character/EncumbranceTests.cs:87. *Fix:* Rename the namespace (for example `Tests.Loot`).
- **TST-012** · **Low** — **Phase5IntegrationTests leaves an untracked results file in the project root.** `Phase5IntegrationTests.RunAll` writes `phase5_6_test_results.txt` to `Application.dataPath/..`, which .gitignore does not cover. *Evidence:* Assets/Scripts/Tests/Encounters/Phase5IntegrationTests.cs:80-89. *Fix:* Write to `Application.persistentDataPath` or `Temp/`, or add the file to .gitignore.

## Dead code, duplication and tech debt

- **TST-013** · **Med** — **Test code compiles into the game assembly and ships in player builds.** There is no `.asmdef`/`.asmref` in Assets, no `com.unity.test-framework` and no `#if` guard under Tests/, so a test compile error breaks the game build and the three MonoBehaviour suites appear in the Add Component menu. *Evidence:* `find Assets -name '*.asmdef' -o -name '*.asmref'` (none); Packages/manifest.json; Assets/Scripts/Tests/Combat/FlankingReachRulesTests.cs:4-10. *Fix:* Move Tests/ into its own Editor-only (or `defineConstraints`) asmdef, then wrap suites in Unity Test Framework `[Test]` cases.
- **TST-014** · **Med** — **Test exceptions are not isolated.** Tests/ has only two `catch` blocks (Phase5IntegrationTests' file write, one WizardSpellProgressionTests check), so any other exception aborts the rest of a suite before its pass/fail summary and, under `ServiceTestRunner.RunAll`, skips every later suite. *Evidence:* Assets/Scripts/Tests/Encounters/Phase5IntegrationTests.cs:86; Assets/Scripts/Tests/Magic/WizardSpellProgressionTests.cs:390; Assets/Scripts/Tests/Services/ServiceTestRunner.cs:32-42. *Fix:* Wrap each test method, or each suite in a runner, in try/catch that logs the exception as a FAIL.
