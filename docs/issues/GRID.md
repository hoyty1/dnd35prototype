# Known issues: Grid and movement (GRID-)

## Bugs and rules deviations

- **GRID-003** · **Med** · Player-visible — **Movement highlight includes squares that cannot be reached.** `MovementService.CalculateMovementRange` offers every cell within straight-line distance that passes `MovementService.IsValidMoveDestination` (the path's end rule; since GRID-001, 2026-10-14, a swarm may end on an enemy) and is not an intact Wall of Ice or Wall of Force square (`SquareGridUtils.IsCellBlockedByWall`, batch 12 step 23), ignoring intervening walls, spheres, detours and the cost of difficult terrain (which the A*, the path trim and the PC move budget do count since batch 12 step 23, `SquareGridUtils.StepCost`; the old GRID-002). On click, `FindPathAoOAware` trims or cuts the path, so the character silently stops short. *Evidence:* Assets/Scripts/Services/MovementService.cs (`CalculateMovementRange`); Assets/Scripts/Grid/SquareGrid.cs (`FindPathAoOAware`). *Fix:* compute the highlight with a Dijkstra flood using the A* rules and `SquareGridUtils.StepCost`, and reject unreachable clicks.
- **GRID-004** · **Med** · Player-visible — **`CharacterController.FiveFootStep` rejects any occupied target cell.** It refuses a cell whose `IsOccupied` is set, counting corpses and the mover itself, while `MovementService.IsValidAdjacentStepDestination` uses `CanPlaceCreature`: corpse squares are offered and then fail, and Large or bigger creatures cannot step +x, +y or +x+y. The wall, corner and sphere checks both now share (`SquareGridUtils.IsStepBlockedByBarrier`, batch 12 step 23, GRID-013). *Evidence:* Assets/Scripts/Character/Controller/CharacterController.cs (`FiveFootStep`); Assets/Scripts/Services/MovementService.cs (`IsValidAdjacentStepDestination`). *Fix:* use `CanPlaceCreature(target, size, this)` in `FiveFootStep`.
- **GRID-005** · **Med** · Player-visible — **Tiny and smaller creatures take a full square and have 5-ft reach.** `SizeCategory.GetSpaceWidthSquares` returns 1 and `GetNaturalReachFeet` 5 ft for Fine, Diminutive and Tiny, and only swarms may share squares, so they attack from adjacent squares. RAW they have 0-ft reach and must enter the target's square, provoking an AoO. *Evidence:* Assets/Scripts/Combat/Core/SizeCategory.cs:81-107, 120-135; Assets/Scripts/Grid/SquareGrid.cs:455-475. *Fix:* allow several Tiny-or-smaller occupants per cell (already supported for swarms) and set reach 0 with an AoO on entry. Attacking into one's own square already works: since CMB-131 (2026-10-08) `CharacterController.CanMeleeAttackDistance` accepts distance 0 and `ThreatSystem.GetThreatenedSquares` keeps the creature's own squares, for every creature with a weapon that can attack an adjacent foe. When Tiny-or-smaller creatures may share a larger creature's space, `CombatFlowService.CanPerformWithdraw` and the shared legality check (`MovementService.CanStartMovement`, since batch 12 step 22 used by the PC Withdraw button and every AI or compulsion withdraw executor, through `CombatFlowService.CanPerformWithdraw` for the button) must also refuse a withdraw by a smaller creature in a space occupied by a larger opponent that threatens that space, unless that opponent has only a reach weapon (DMG p.29, PHB p.113; delegated RAW reading 2026-10-14, recorded in RULES_COVERAGE 4.1; a same-size square-mate after a pin release may still withdraw, owner ruling 2026-10-08, CMB-131).
- **GRID-006** · **Med** · Player-visible — **Overlapping difficult-terrain spells clear each other's cells.** `MovementService` stores difficult terrain as a plain `HashSet<Vector2Int>` without reference counting, so when one of two overlapping effects ends it removes cells the other still covers. Normal movement and the charge both read the set through `MovementTerrain.IsDifficultTerrain` (since 2026-10-29), so a still-greased square cleared this way is open ground for both (the per-mover exemptions read the zones that cover a square of the set, `MovementTerrain.ZoneHindersMovement`, but only for a square still in the set). No map terrain feeds the set. Since batch 11 step 25 (2026-10-16) the whole set is cleared when all areas are cleared (`GameManager.ClearAreaDifficultTerrain`, from `ClearAllActiveGreaseEffects` and `RestorePartyAfterCombat`, which calls `MovementService.ClearDifficultTerrain`), so no area's squares outlive a fight. *Evidence:* Assets/Scripts/Services/MovementService.cs:57, 734-751; Assets/Scripts/Spell/Special/GameManager_Grease.cs:407, 521-524. *Fix:* reference-count cells per source and add a data-driven map terrain source.
- **GRID-007** · **Low** · Player-visible — **A* misjudges threats for multi-square movers.** The +200 `THREAT_COST` applies only when the base square is threatened, while `AnalyzePathForAoOs` checks every footprint square a step vacates, so Large+ creatures can take unweighed AoOs (not verified in Play mode). The start check no longer strands a mover that shares its square: since 2026-10-08 it checks only that the footprint is on the grid (CMB-122). *Evidence:* Assets/Scripts/Grid/SquareGrid.cs (`FindPathAoOAware`, the `threatenedSquares.Contains(current)` cost term); Assets/Scripts/Services/MovementService.cs (`FindPath`). *Fix:* penalise any threatened footprint square the step vacates: since 2026-10-14 `AnalyzePathForAoOs` provokes only for the squares a step vacates (previous footprint minus new footprint; delegated RAW reading, GRID-023), and the A* cost should use the same rule.
- **GRID-008** · **Low** — **Reach of 15 ft or more over-threatens diagonals.** `ThreatSystem` measures threat with Chebyshev distance (diagonal = 1), so a (3, 3) offset counts as 3 squares; RAW uses the 1-2-1 count (20 ft) except for 10-ft reach. *Evidence:* Assets/Scripts/Combat/Core/ThreatSystem.cs:115-133. *Fix:* use `SquareGridUtils.GetDistance` for reach of 3+ squares and keep the 10-ft special case.
- **GRID-025** · **Med** · Player-visible — **Terrain, areas and barriers test only a mover's anchor square.** `SquareGridUtils.StepCost`, `IsDifficultTerrainForMovement` and `IsStepBlockedByBarrier` (since 2026-10-29 the per-mover square question `MovementTerrain`, with the mover's exemptions, still asked for the anchor square only), `GreaseStepHook` (`IsCellInArea(to)`/`(from)`) and the 5-foot step's destination test read the anchor square of a step, so a Large or bigger mover whose other squares enter grease, a web or a wall square pays no difficult-terrain cost, makes no Balance check and is not blocked, while the caster-turn save and the zone registry (`PersistentAreaEffect.IsCharacterInArea`) use the whole footprint. PHB p.148: a creature moves only as fast as the most difficult terrain it occupies. *Evidence:* Assets/Scripts/Grid/SquareGridUtils.cs (`StepCost`, `IsStepBlockedByBarrier`); Assets/Scripts/Services/MovementStepHooks.cs (`GreaseStepHook`). The charge is footprint-aware (every square of its swept space and of its end space asks `MovementTerrain.Classify`), so a 2x2 creature may walk with part of its space through grease or a wall square that bars its charge. *Fix:* test every square of `mover.GetOccupiedSquaresAt(to)` (and at `from`) with `MovementTerrain` in the step rules and the Grease hook (the mover is already passed in); add a Large-creature grease scenario. Filed 2026-10-29 (batch 12 step 23 review); not verified in Play mode.
- **GRID-026** · **Low** · Player-visible — **A creature balancing in grease is not flat-footed and is not checked again when damaged.** Grease sends the reader to the Balance skill (PHB p.237), which makes a creature balancing flat-footed unless it has 5 or more ranks in Balance, and calls for a new check against the same DC when it takes damage while balancing (PHB p.67). `GreaseAreaEffect.CheckMovement` rolls only the movement check. *Evidence:* Assets/Scripts/Spell/AreaEffects/GreaseAreaEffect.cs (`CheckMovement`). *Fix:* mark a creature that moved in grease this round as balancing, deny its Dex bonus to AC through the shared AC path when it has fewer than 5 Balance ranks, and roll the DC 10 check on damage through the shared damage path (PC and NPC alike). Filed 2026-10-29 (batch 12 step 23 review).
- **GRID-020** · **Low** · Player-visible — **The path preview and the A* threat cost ignore the per-round movement opportunity record.** Since CMB-128 (owner ruling 2026-10-08, PHB p.138) an enemy gets one movement AoO per mover per round, recorded on the mover (`ThreatSystem.HasHadMovementOpportunity`), and `AnalyzePathForAoOs` skips an enemy whose opportunity already came, so the PC AoO confirmation prompt and the AI's provoke counts are right. `ThreatSystem.GetSquaresThreatenedByEnemies`, the one set behind the hover preview (`GameManager.GetPreviewThreatenedSquares`, read by `UpdatePathPreview`) and the PC click path's route preference (`MovementService.FindPath(avoidThreats: true)`, which hands `FindPathAoOAware` a cost of 200 per threatened square; since GRID-001, 2026-10-14, both read this one builder), still builds it from every living enemy. On the second move of a double move, or a move after a bull rush follow, the hover preview still draws red provoking segments for an enemy that will no longer attack, and the pathfinder still detours around its squares. The same sets also ignore enemies with no AoO left this round (older behaviour). *Evidence:* Assets/Scripts/Combat/Core/ThreatSystem.cs (`GetSquaresThreatenedByEnemies`); Assets/Scripts/_Core/GameManager.cs (`GetPreviewThreatenedSquares`, `UpdatePathPreview`); Assets/Scripts/Services/MovementService.cs (`FindPath`). *Fix:* skip enemies for which `ThreatSystem.HasHadMovementOpportunity(enemy, mover)` is true (and optionally those with no AoO left) in `GetSquaresThreatenedByEnemies`, and invalidate the preview cache when a movement opportunity is recorded. Not verified in Play mode.
- **GRID-024** · **Low** · Player-visible — **Ordinary movement cannot pass a helpless opponent's square.** PHB p.147: a square occupied by a helpless opponent (unconscious, dying, asleep, paralyzed, bound) may be moved through without penalty, and p.148 lets a mover end its movement there. Ordinary pathing (`MovementService.FindPath` with `allowThroughEnemies` false, used by the PC Move button, the AI moves, the compulsion moves and the overrun's "Normal Move" branch) treats every living enemy's square as blocked, so a creature must walk around a sleeping goblin. Only two movers pass such a square: the overrun move (batch 12 step 20: `GameManager.GetOverrunOpponentsAt` skips helpless occupants, `rules/overrun-helpless-pass`) and the charge (PHB p.154; CMB-132, CMB-199 fixed 2026-10-29: `ChargeRules.LetsChargePass` and `ExecuteCharge` passing `allowThroughEnemies` short of its end, `rules/charge-past-helpless`). Both read one test, `ChargeRules.IsPassableHelpless` (the overrun through `IsPassableHelplessOpponent`). A charge may pass such a square but never ends in one, not even when it is stopped there (owner ruling 2026-10-29: the charger moves back to the last clear square it passed, `GameManager.EndChargeInClearSpace`, `rules/charge-interrupted-on-helpless`); the ruling covers charges only, so an ordinary move may still end in a helpless creature's square once this is fixed (PHB p.148). Found in the step 20 review, 2026-10-29; not verified in Play mode. *Evidence:* Assets/Scripts/Services/MovementService.cs (`FindPath`); Assets/Scripts/Grid/SquareGrid.cs (`FindPathAoOAware`); Assets/Scripts/Combat/Maneuvers/ChargeCore.cs (`ChargeRules.IsPassableHelpless`). *Fix:* let the A* pass (and end on) squares whose only enemy occupants are helpless (`ChargeRules.IsPassableHelpless`), for every mover, and have `MoveAlongPath` accept them.
- **GRID-027** · **Med** · Player-visible — **Flight is not modelled.** No movement mode exists: fly speeds are `SpecialAbilities` strings and `Fly` creature tags (read only by Gust of Wind and the skeleton template), and every mount has `CanFly` false. PHB p.148: flying creatures are not hampered by difficult terrain, so they pass over the ground zones (Grease, Web, Spike Stones, Entangle, Soften Earth, Plant Growth) that bar a walker's charge; eagles, hawks, owls, bats, giant wasps and bees, lantern archons, arrowhawks, yeth hounds and the incorporeal undead fly. The per-mover square question's exemption `MovementTerrain.IgnoresDifficultTerrain` (owner ruling 2026-10-29) is where a fly mode joins; it holds only the incorporeal exemption today. Found mapping the charge line hindrances (2026-10-29). *Evidence:* Assets/Scripts/Grid/MovementTerrain.cs (`IgnoresDifficultTerrain`); Assets/Scripts/Spell/AreaEffects/GustOfWindEffect.cs; Assets/Scripts/Combat/Mounts/MountData.cs (`CanFly`). *Fix:* give creatures a fly speed and maneuverability as data, let a flier move and charge by it, and answer `IgnoresDifficultTerrain` for a creature that is flying; walls still block it.
- **GRID-028** · **Med** · Player-visible — **A creature's space comes only from its size, so swarms are stored as Large and get a Large size modifier.** The footprint is always `SizeCategory.GetSpaceWidthSquares` of the creature's size (`CharacterController.GetVisualSquaresOccupied`, Assets/Scripts/Character/Controller/CharacterController.cs; `GameManager.NPCSetup.cs` spawn placement; the summon placement in `GameManager.SpellCasting.cs`, `GameManager.CastCore.cs` and `GameManager.CastDeciders.cs`), and nothing on `NPCDefinition` or `CharacterStats` can set a space apart from size. To get a swarm's 10-ft space, `bat_swarm` (NPCDatabase_B.cs), `rat_swarm` (NPCDatabase_R.cs) and `spider_swarm` (NPCDatabase_S.cs) store `SizeCategory.Large`. `CharacterStats.ArmorClass` and `TouchArmorClass` then add `SizeModifier` (`SizeCategory.GetAttackAndAcModifier`, Large -1), and the Hide size modifier is Large's -4. The bat swarm gets AC 11, touch 11 and flat-footed 9 where the MM has a Diminutive swarm at AC 16, touch 14, flat-footed 12 (+4 size, MM p.237). The rat swarm also gets 11/11/9 where the MM has a Tiny swarm at 14/14/12 (+2 size, MM p.239). The spider swarm gets 12/12/9 where the MM has 17/17/14 (MM p.239-240). The swarms stored at their true Diminutive size (`centipede_swarm`, `locust_swarm`, `hellwasp_swarm`) have the opposite fault: one square instead of the 10-ft space the MM gives each of them (MM p.238-239). The swarm subtype (MM p.315-316) makes a swarm's size that of its component creatures (Fine, Diminutive or Tiny), and each of these stat blocks lists Space/Reach 10 ft./0 ft. CRE-196 (rat) and CRE-241 (spider, which calls the Large size a possibly intentional deviation for the owner) record the size only as a data difference; GRID-005 covers the 1-square footprint and 5-ft reach of Tiny-and-smaller creatures, not a swarm's space. *Evidence:* Assets/Scripts/Combat/Core/SizeCategory.cs (`GetSpaceWidthSquares` returns 1 for Fine to Medium; `GetAttackAndAcModifier`); Assets/Scripts/Character/Stats/CharacterStats.cs (`SizeModifier`, `ArmorClass`, `TouchArmorClass`); the comments on the three Large swarms' NaturalArmorBonus claim the MM AC that the formula does not give; MM p.237-240, p.315-316; PHB p.134 (size modifiers). *Fix:* add a space (in squares or feet) to `NPCDefinition` and `CharacterStats`, cloned in `NPCDefinition.Clone`, the templates' `CopyDefinitionFields` and `ResetForNewCreature`, defaulting to `GetSpaceWidthSquares`. Read it in every footprint and placement path. Set the swarms to their MM size with a 10-ft space and reach 0, then rerun CreatureImmunityRulesTests (which builds the three Large swarms) and the soak. Found by the MM stat-block audit of 2026-11-16. Not verified in Play mode.
- **GRID-029** · **Med** · Player-visible — **3 rules of the PHB terrain, squeezing and creature size rules have no rules path in play, one of them outside a charge and an overrun move (PHB p.148-150).** Squeezing (PHB p.148): a creature may squeeze into or through a space at least half as wide as its own (an ogre through a 1-square gap), each move into or through it counts double, and it may pass an opponent but not end there; for a space under half its width it needs Escape Artist (PHB p.73) and cannot attack, takes -4 AC and loses its Dexterity bonus to AC; the game has no squeezing, so a Large creature cannot pass a 1-square gap between opponents or an opponent and the grid edge, a Huge one cannot pass a 2-square gap, `SquareGridUtils.StepCost` only knows diagonals and difficult terrain, and Escape Artist has no tight-space use (the -4 attack and AC modifier while squeezed: see CMB-238). Moving through a much larger or smaller creature (PHB p.148): any creature may move through the square of a creature three size categories larger, and a big creature through one three categories smaller, unless it fills its squares; the game decides pass-through by team only (allies, dead occupants, or enemies only when the caller sets `allowThroughEnemies`: overrun, charge past a helpless foe, swarms), so a Small creature cannot pass a Huge enemy and a Large one cannot pass a Tiny enemy. Ending movement in an illegal space (PHB p.148): a creature whose move ends where it may not stop (stunned by an attack of opportunity in an ally's square) goes back to its last legal or closest legal position; the game has such a fallback only for a charge stopped in a helpless creature's square (`GameManager.EndChargeInClearSpace`, `Assets/Scripts/Combat/Maneuvers/ChargeCore.cs`; owner interpretation 2026-10-29) and for an overrun move stopped in a square it only passes through (`GameManager.RunOverrunMove`, `Assets/Scripts/Combat/Maneuvers/OverrunSystem.cs`: back to the last square it stood alone in, but not when an attack of opportunity stopped it or it is incapacitated), and none for any other move, so a mover stopped in an ally's square (incapacitated, knocked prone or held by an attack of opportunity, a refused step, Entangle or Spike Stones) is registered in that cell and two creatures share one square. *Evidence:* `SquareGrid.CanTraversePathNode`, `CanPlaceCreature`, `FindPathAoOAware` (`Assets/Scripts/Grid/SquareGrid.cs`); `SquareGridUtils.StepCost`, `CalculatePathCost`; `MovementService.FindPath`, `IsValidMoveDestination`, `IsStepRefused` (`Assets/Scripts/Services/MovementService.cs`); `CharacterController.MoveAlongPath` (end-of-path `RefreshGridOccupancy`); `GameManager.ExecuteMovement` (`Assets/Scripts/Combat/Actions/Executors/GameManager.MoveAction.cs`); `ExecutePathWithMovementAoOs` (`Assets/Scripts/_Core/GameManager.CombatActions.cs`); the PC and the AI share this code, so both lack the rules; PHB p.73, p.148. *Fix:* build each rule in the shared code for PCs and NPCs alike. Found by the PHB combat chapter audit of 2026-11-17. Not verified in Play mode.
- **GRID-030** · **Med** · Player-visible — **Closest creature for a confused creature differs from the PHB (PHB p.147).** Tie between equally close creatures: the game takes the first in list order (a strict less-than scan of `GameManager.GetAllCharactersForAI`, no die roll), the PHB rolls a die to decide which counts as closest. Distance to the nearest creature: the game measures `SquareGridUtils.GetDistance(actor.GridPosition, candidate.GridPosition)` between anchor (lowest-corner) squares, so a Medium confused creature at (5,5) beside a Large creature covering (3,3)-(4,4) measures 3 squares to it instead of 1 and picks a Medium creature 2 squares away as nearest; the PHB measures from the nearest square of each space (PHB p.147, as for reach, PHB p.137). The ward and visibility gaps of the same selector are in AI-050 (see AI-050). *Evidence:* `ConfusedBehaviorController.FindNearestCreature`, `TryRollDecision` (`Assets/Scripts/Combat/Behaviors/ConfusedBehaviorController.cs`), read for PCs and NPCs alike through the turn compulsion; PHB p.137, p.147. *Fix:* make the rule match the PHB in the shared, actor-agnostic code that the PC UI and the AI both call, then rerun the static suites and rules scenarios that cover it. Found by the PHB combat chapter audit of 2026-11-17. Not verified in Play mode.

## Unreachable or stubbed features

- **GRID-009** · **Med** · Player-visible — **No line of sight; line of effect applies only to area spells and summon placement.** `CharacterController.CanSee` checks only total concealment, and `LineOfEffectService` is read only through `AoESystem`: the cast core's area-origin and summon-placement legality, area cell and target filtering, Grease, Turn Undead and the AI's area aim. So Wall of Ice and Wall of Force do not block attacks or single-target spells, and Wall of Fire never blocks sight or targeting. Only Resilient Sphere blocks attacks, AoOs and single-target spells, for every attack kind and every PC or NPC cast, through `AttackLegality.CanDirectlyAttack` (the cast core's `CheckCastDirectAttackLegality` included), `ThreatSystem` and the AI's target choice; its remaining gaps are CMB-092. *Evidence:* Assets/Scripts/Character/Controller/CharacterController.cs:11087-11096; Assets/Scripts/Spell/AreaEffects/AoESystem.cs:1039-1290; Assets/Scripts/Spell/Resolution/GameManager.CastCore.cs:485-521, 567, 637; Assets/Scripts/Combat/Core/AttackLegality.cs:82. *Fix:* add a `LineOfEffectService` check to attack and single-target spell validation, highlighting and AI targeting.

## Development traps

- **GRID-010** · **Low** — **`SquareGrid.Instance` is overwritten by every `Awake` and never cleared.** Test suites that create and `DestroyImmediate` extra grids (10 files, e.g. OverrunRulesTests, GustOfWindRulesTests) overwrite it. `StaticSuiteRunner` restores it after each suite run (lines 757, 814-815), but a grid destroyed outside the runner leaves `Instance` dangling. Impact is limited because it is only a fallback when `GameManager.Instance` or `GameManager.Grid` is null. *Evidence:* Assets/Scripts/Grid/SquareGrid.cs:12, 25-28; Assets/Scripts/Character/Controller/CharacterController.cs:4200, 15839; Assets/Scripts/_Core/GameManager.cs:5105, 5336, 5422. *Fix:* assign only if null and clear in `OnDestroy`.

## Performance

- **GRID-011** · **Low** — **Ungated `Debug.Log` on movement-preview paths.** `UpdatePathPreview` still runs every frame during movement selection, but it now recomputes only when the hovered cell changes (`HasCoordChanged`) and caches the threatened squares (`GetPreviewThreatenedSquares`). Each recompute still logs its own `[PathPreview]` line and the A* result (`SquareGrid`). Through `MovementService.FindPath` -> `CheckForAoO` -> `ThreatSystem.AnalyzePathForAoOs` it also logs one `GetThreatenedSquares` line per enemy and the path analysis. *Evidence:* Assets/Scripts/_Core/GameManager.cs:2236, 11500-11557, 11626; Assets/Scripts/Services/MovementService.cs:314, 333; Assets/Scripts/Combat/Core/ThreatSystem.cs:97, 153, 499, 590-594; Assets/Scripts/Grid/SquareGrid.cs:307, 322, 380. *Fix:* gate the verbose logs behind a debug flag or `[Conditional]` wrapper.
- **GRID-012** · **Low** — **`SquareGrid.ClearCreatureOccupancy` scans every cell on each `RefreshGridOccupancy`.** That runs on every movement step and size change; 400 cells on the default 20x20 grid is negligible but grows with map size. *Evidence:* Assets/Scripts/Grid/SquareGrid.cs:166-178; Assets/Scripts/Character/Controller/CharacterController.cs:4364-4370. *Fix:* track each creature's occupied cells and clear only those.
