# Known issues: Creatures, templates and summoning (CRE-)

## Bugs and rules deviations

- **CRE-001** · **High** · Player-visible — **Templates are applied twice at encounter spawn.** Skeleton, zombie and lycanthrope factories record their own template in `AppliedTemplateIds`, and `GameManager.BuildEncounterDefinitionForSpawn` reapplies that list with no already-applied check. Skeletons get DEX +2 twice, zombies double HD again, most were-creatures re-add animal stats and dungeon celestial/fiendish entries stack their bonuses (not verified in Play mode). *Evidence:* Assets/Scripts/_Core/GameManager.cs:2830-2861; Assets/Scripts/Character/Templates/SkeletonTemplate.cs:246. *Fix:* split pending and applied template lists, or skip templates already applied.
- **CRE-002** · **High** · Player-visible — **Spawned NPCs have no alignment.** `GameManager.InitializeNPCFromDefinition` never copies `NPCDefinition.CharacterAlignment`, so about 160 aligned database entries spawn as `Alignment.None` (only some test encounters and Summon Monster set it by hand). Template smite, Holy Avenger, Protection from/Magic Circle against alignment and alignment-targeted spells never see ordinary monsters as evil or good. *Evidence:* Assets/Scripts/_Core/GameManager.NPCSetup.cs:554-671, 320-442; Assets/Scripts/Combat/Special/TemplateSmiteSystem.cs:108. *Fix:* copy the alignment in InitializeNPCFromDefinition, then drop the redundant overrides.
- **CRE-003** · **High** · Player-visible — **Summon aliases overwrite real Monster Manual creatures.** `NPCDatabase.RegisterSummonCreatureAliases` runs last in `Init` and replaces badger, riding_dog, owl, raven and giant_bee with clones of dire_badger, dog, eagle and the Large dire_bat. Summon Monster I-II, the creature_showcase preset and figurine/bag wondrous items get the wrong stat block. *Evidence:* Assets/Scripts/Character/Creatures/NPCDatabase.cs:59, 238-269; Assets/Scripts/Spell/Components/SummonMonsterLists.cs:135-161. *Fix:* delete those five aliases (keep wolf, the only new ID) and make `RegisterSummonAlias` skip existing IDs.
- **CRE-004** · **High** · Player-visible — **Spawned NPCs ignore class BAB and saves.** `InitializeNPCFromDefinition` always sets `UseCreatureTypeProgression`, so BAB and saves follow creature-type progressions (or overrides) and `NPCDefinition.BAB` is never read (human_paladin: BAB 5 in data, +3 spawned). `CreatureClassEngine.ApplyClassToDefinition` adds class HD, HP and CR but no effective BAB, saves, feats or skills, and replaces racial HP when `BaseHitDieHP = 0`. *Evidence:* Assets/Scripts/_Core/GameManager.NPCSetup.cs:593-599; Assets/Scripts/Character/CreatureClass/CreatureClassEngine.cs:140-175. *Fix:* apply class BAB/save progressions to class HD (e.g. via the overrides).

## Development traps

- **CRE-022** · **Med** · Player-visible — **Creature IDs silently overwrite each other.** `NPCDatabase.Register` has no duplicate check and `Init` registers files in a hand-kept, non-alphabetical order, so the later entry wins in 5 collisions (dretch, skeleton_archer and 3 more). Two creatures also exist under two IDs used by different consumers (large_viper/viper_large, huge_monstrous_centipede/monstrous_centipede_huge). The `dretch` that wins (`RegisterDretch`) has Str 14 where MM p.42 gives 12 (the losing `RegisterSummonDretch` has 12), so every dretch, summoned or encountered, gets +1 to melee attack and damage rolls; SummonMonster3CreaturesTests fails on it (2026-10-07). *Evidence:* Assets/Scripts/Character/Creatures/NPCDatabase.cs:18-62, 212-226; Assets/Scripts/Spell/Components/SummonMonsterLists.cs:200, 542. *Fix:* warn on duplicate IDs, delete or rename the losers, and merge each double-ID creature into one ID or an explicit alias.
- **CRE-023** · **Med** — **Template adapters and `NPCDefinition.Clone` copy hand-picked fields.** The skeleton, zombie and lycanthrope adapters copy back only about 33-37 fields, losing the factories' clearing of breath weapons, auras and regeneration (latent today). Clone is partly shallow and its SwarmTraits copy drops `SwarmDamageCount`; a new NPCDefinition field must be added to Clone, three `CopyDefinitionFields` methods and the factories. *Evidence:* Assets/Scripts/Character/Templates/SkeletonCreatureTemplate.cs:41-93; Assets/Scripts/Character/Creatures/NPCDatabase.cs:641-739. *Fix:* have the adapters replace the definition wholesale and make Clone deep-copy reference fields.
- **CRE-024** · **Med** — **Monsters carry placeholder class levels.** 250 database entries use `CharacterClass = "Warrior"` for racial HD, which becomes a real Warrior level, so `IsWarrior` and `HasClass("Warrior")` are true for monsters (no production reader yet). Skeletons and zombies get Fighter 1 from `EnsureMulticlassDataInitialized`, so `IsFighter`, `AISpellcastingStrategist.IsFrontliner` and WishExecutor treat them as fighters. *Evidence:* Assets/Scripts/Character/Stats/CharacterStats.cs:355-387, 3345-3356; Assets/Scripts/Character/Templates/SkeletonTemplate.cs:73-74. *Fix:* use an explicit racial-HD marker, or skip the Fighter fallback under `UseCreatureTypeProgression`.
- **CRE-025** · **Low** — **The creature count is only known at runtime.** `NPCDatabase.Init` registers about 30 partial files, generates dragons in a loop and adds aliases, so the authoritative number is the "[NPCDatabase] Initialized with N NPC types." log line. A static count (about 317 `Register(` calls, up to 60 dragons, plus aliases) suggests about 380-390 (not verified in Play mode). *Evidence:* Assets/Scripts/Character/Creatures/NPCDatabase.cs:20-61. *Fix:* quote the runtime log line instead of hard-coding a count in docs or tests.
- **CRE-033** · **Low** — **Creature type and tag spell "Magical Beast" two ways.** 26 definitions use `CreatureType = "Magical Beast"` and 4 use `"MagicalBeast"` (plus `BaseCreatureDefinitions`); `CreatureTags` mix both too. `CreatureTypeProgression` accepts both, but exact-string checks such as ranger favored enemies (`FavoredEnemyData`, "Magical Beast") and tag matching miss the other spelling.
