# Known issues: Runtime loop and core (CORE-)

## Bugs and rules deviations

- **CORE-001** · **High** · Player-visible — **Party wipe soft-locks the game; there is no defeat screen.** When all PCs die, 14 inline `AreAllPCsDead()` blocks set `TurnPhase.CombatOver`, show "DEFEAT!" and hide the action buttons; no defeat path returns to encounter selection, so the player must stop Play mode or quit. *Evidence:* Assets/Scripts/_Core/GameManager.NPCTurns.cs:67 (and 3 more there); Assets/Scripts/Spell/Resolution/GameManager.SpellCasting.cs:2448 (and 7 more there). *Fix:* Add one `HandleCombatDefeat()` with a defeat panel (Retry / Return to encounter selection / Quit) and call it from all 14 blocks. *Reproduced by scenario:* the AI-vs-AI soak (`soak/dmg-random-encounters`, seeds 1-50, batch 20261007-204349, docs/TESTING.md 3.5) reached a party wipe 5 times (seeds 8, 20, 26, 30: Defeat set by the game; seed 48: DefeatUndetected). The harness halts the fight at CombatOver, so it shows the defeat end but not the missing exit; the soft lock itself is still unverified in Play mode.
- **CORE-002** · **Med** · Player-visible — **An ordinary victory skips the `OnCombatEnded` cleanup.** Victory resets through `TurnService.ForceResetWithoutCallbacks`, so `AIService.ClearAuraSaveImmunities`, `EffectService.ClearAll`, `ConditionService.CleanupOnCombatEnd`, the bardic-music stop and the `CombatEndedEvent` publish never run. Aura immunities are keyed by instance ID on reused NPC slots, so a PC's immunity can carry into a later encounter. *Evidence:* Assets/Scripts/Services/TurnService.cs:186-215; Assets/Scripts/_Core/GameManager.cs:3836-3875. *Fix:* Extract that cleanup into one method called from victory, defeat and `ResetCombatStateForNextEncounter`.
- **CORE-003** · **Med** · Player-visible — **Tick kills end combat late, then the PC phase overwrites `CombatOver`.** Flaming Sphere, Wall of Fire and Melf's Acid Arrow ticks have no victory check, so victory is caught only when `StartPCTurn` runs `EndAttackSequence`, after which `StartPCTurn` sets `TurnPhase.PCTurn` while the loot window opens (not verified in Play mode). *Evidence:* Assets/Scripts/_Core/GameManager.cs:3539-3563, 4055, 4064; Assets/Scripts/Spell/Special/GameManager_FlamingSphere.cs:543-571. *Fix:* Check victory from one post-damage hook and return early from `StartPCTurn` if the phase is `CombatOver`. The scenario harness waives its `phase-after-combatover` invariant under this issue; the 50-fight soak of 2026-10-07 (docs/TESTING.md 3.5) never triggered it, since no fight there used a ticking spell.
- **CORE-004** · **Med** · Player-visible — **A test encounter preset permanently replaces the created party.** The `Configure*TestParty` methods re-`Init` PC1-PC3 with hard-coded stats (32 `PCn.Init` calls) and the creation data is not stored, so a later normal preset only reactivates the PC objects and the test characters stay. *Evidence:* Assets/Scripts/_Core/GameManager.TestConfigs.cs:1857-1863; Assets/Scripts/_Core/GameManager.cs:723-749, 1863-1895. *Fix:* Snapshot the party before a test preset and restore it for normal presets, or hide test presets behind a dev flag.
- **CORE-005** · **Med** · Player-visible — **Initiative tie-break comparator is inconsistent.** `TurnService.SortInitiativeOrder` breaks full ties with `Random.Range(0, 2)` inside the `List.Sort` comparator, so `Compare(a, b)` and `Compare(b, a)` can disagree. Up to 16 combatants this only randomizes tie order; above 16 with exact ties the sort can misbehave or throw (not verified in Play mode). *Evidence:* Assets/Scripts/Services/TurnService.cs:122-133. *Fix:* Pre-roll a tiebreak value per `InitiativeEntry` and compare on it.
- **CORE-034** · **High** · Player-visible — **Downed regenerating or fast-healing enemies stall combat forever.** `AreAllNPCsDead` treats any enemy at HP <= 0 with `HasRegeneration` or a "regeneration"/"fast healing" ability as not defeated, with no `IsDead` check. Its turn is skipped before `ApplyRegenerationAtTurnStart` runs (and that method stops at -10), so it never recovers or counts as defeated, and the fight cannot be won. *Evidence:* Assets/Scripts/_Core/GameManager.cs:3337-3420, 3909-3917, 10930-10938; Assets/Scripts/Character/Controller/CharacterController.cs:3844-3847; Assets/Scripts/_Core/GameManager.NPCTurns.cs:49-59. *Fix:* Count dead creatures as defeated, tick regeneration before the skip gate, and treat a regenerator as defeated once it cannot recover.
- **CORE-035** · **Med** · Player-visible — **Daily recovery never runs: ability damage and disease are permanent.** EffectService.ProcessDailyEffects (disease progression, 1 point/day ability-damage recovery) runs only when one combat's round counter hits a multiple of RoundsPerDay = 14400, and TurnService restarts rounds at 1 each combat; CharacterStats.ApplyCompleteRest has no non-test caller and the post-combat rest does not heal ability damage. Ability damage therefore accumulates across encounters and diseases never progress or recover. *Evidence:* Assets/Scripts/_Core/GameManager.cs:204, 3832-3833; Assets/Scripts/Spell/Effects/EffectService.cs:617-629; Assets/Scripts/Character/Stats/CharacterStats.cs:1640; Assets/Scripts/_Core/GameManager.cs:868-1043. *Fix:* Drive ProcessDailyEffects (or ApplyCompleteRest) from the rest/day clock, e.g. once per RestorePartyAfterCombat or per in-game day, instead of the per-combat round count.
- **CORE-036** · **Med** · Player-visible — **Post-combat rest erases all negative levels, including resurrection level loss.** RestorePartyAfterCombat calls RemoveAllConditions and ClearAllConditions, which remove every EnergyDrained stack, including the permanent (-1 duration) negative level that Resurrection and Wish resurrection apply as their level-loss cost. There is no 24-hour Fortitude save and no conversion to real level loss, so energy drain and resurrection penalties vanish after one fight. *Evidence:* Assets/Scripts/_Core/GameManager.cs:939-940; Assets/Scripts/Services/ConditionService.cs:130-150; Assets/Scripts/Spell/Resolution/GameManager_Spells_Phase2.cs:546; Assets/Scripts/Spell/Special/WishExecutor.cs:583. *Fix:* Exclude EnergyDrained from the rest wipe, add the 24-hour Fortitude save per negative level, and apply resurrection cost as real level loss.
- **CORE-037** · **Med** · Player-visible — **Defeat counts the PCs list with a plain HP test, while victory counts Team == Enemy with a regeneration exception.** `AreAllPCsDead` iterates only the party `PCs` list and returns false while any PC has CurrentHP > 0. `AreAllNPCsDead` and `GetAliveNPCCount` iterate `NPCs` with Team == Enemy and treat a downed creature with regeneration or fast healing as still alive (a substring match with no IsDead check, CORE-034). So Player-team summons and allies never prevent defeat, a downed PC with fast healing counts as defeated, and a downed regenerating enemy does not. CORE-014 notes the victory scan only. No RAW rule defines combat end, but the same HP states (PHB p.145) apply to everyone. Not verified in Play mode. *Evidence:* Assets/Scripts/_Core/GameManager.cs:3337-3370, :3377-3446; Assets/Scripts/Services/EncounterService.cs:82-100. *Fix:* one `IsOutOfFight(c)` predicate and one `EvaluateCombatEnd()` that applies it per Team over all combatants, called from a central post-damage hook (CORE-011). Found by the PC/NPC parity audit (docs/systems/PC_NPC_PARITY.md); not verified in Play mode. The scenario harness (docs/TESTING.md 3.4) waives its `combat-end-early` invariant and its `combat-end-detected` ends with `cause=unconscious>0` (a side out at positive HP, which the HP-only predicates ignore) under this issue. *Reproduced by scenario:* the AI-vs-AI soak (`soak/dmg-random-encounters`, seeds 1-50, batch 20261007-204349, docs/TESTING.md 3.5). `combat-end-early` once: seed 8 (run 20261007-204356), the game declared defeat while the cleric stood at 0 HP, Disabled and still able to act (PHB p.145), because `AreAllPCsDead` treats HP 0 as out. `combat-end-detected` with `cause=unconscious>0` 7 times (for example seeds 13 and 16 of run 20261007-204505): a side whose last members were unconscious at positive HP (6 victories, and the party in the defeat of seed 48) was never counted as out.

- **CORE-007** · **Low** · Player-visible — **HP calculation mode (Roll/Average/Maximum) has no settings UI.** `GameSettings.hpCalculationMode` (default Roll) is set only by the LeftCtrl+H debug hotkey and read only on level-up, and `GameSettings.Instance` creates a DontDestroyOnLoad GameObject when none exists. *Evidence:* Assets/Scripts/_Core/GameSettings.cs:22-53; Assets/Scripts/Utilities/DebugCommands.cs:21-54; Assets/Scripts/Character/Stats/CharacterStats.cs:3668-3693. *Fix:* Add a settings panel or keep it debug-only, and make the mode a plain static or ScriptableObject setting.
- **CORE-008** · **Low** — **Planar travel and creature trapping are unwired scaffolding.** GameManager instantiates `PlanarTravelSystem` and `CreatureTrapSystem`, but only four setup and item-data helpers are called; `PlaneShift`, `CreateGate`, `TrapCreature` and the rest have no external caller. Latent defects: gates expire on `Time.time`, range checks use `Vector3.Distance`, `TrapCreature` never clears grid occupancy, and plane state is separate from `GameManager.CurrentPlane`. *Evidence:* Assets/Scripts/World/PlanarTravelSystem.cs:207, 704; Assets/Scripts/World/CreatureTrapSystem.cs:222-226. *Fix:* Treat as unimplemented; fix these before wiring anything to them.

## Development traps

- **CORE-009** · **Med** — **`GameManager.Awake` runs before its scene references are assigned.** `SceneBootstrap.SetupGameManager` assigns `Grid`, PCs, NPCs and `CombatUI` after `AddComponent<GameManager>()`, so Awake gives `MovementService` a null Grid and `InputService` a null camera (`Start` repairs both). New Awake code that dereferences these will fail. *Evidence:* Assets/Scripts/_Core/SceneBootstrap.cs:1001-1015; Assets/Scripts/_Core/GameManager.cs:483-583, 610-620. *Fix:* Initialize field-dependent services in Start or a post-assignment Init, or pass lazy getters.
- **CORE-010** · **Med** — **Most `GameEventSystem` events are never published.** Of 20 event structs only `CombatStartedEvent`, `TurnStartedEvent`, `NewRoundEvent` and `CombatEndedEvent` are published (the last not on normal victory or defeat), so subscribing to `DamageTakenEvent` or the other 15 never fires. The only subscriber is `WallOfFireAreaEffect` (`TurnStartedEvent`). *Evidence:* Assets/Scripts/_Core/GameEventSystem.cs:123-300; Assets/Scripts/_Core/GameManager.cs:3735, 3782, 3809, 3849. *Fix:* Publish events at their call sites or delete unused structs, and publish `CombatEndedEvent` from one end-combat path.
- **CORE-011** · **Med** — **Combat end is detected only where each damage path remembers to check.** There is no central on-death hook: defeat is 14 inline `AreAllPCsDead()` blocks and victory about 27 `AreAllNPCsDead()` sites plus `CheckCombatVictory` callers. A new damage source that omits them ends combat only at the next PC turn's safety-net check (CORE-003). *Evidence:* Assets/Scripts/Spell/Resolution/GameManager.SpellCasting.cs (16 victory sites, 2434-6141); Assets/Scripts/_Core/GameManager.cs:3554, 3839. *Fix:* Route every HP-reducing path through one hook that calls a single `EvaluateCombatEnd()`. *Parity audit 2026-10-07:* Parity audit 2026-10-07: AI-run attackers (Player-team summons via AI_SummonedCreature, charmed or confused actors) that kill the last enemy with NPCPerformAttack (melee attack sequence or ranged attack) never trigger victory: only AreAllPCsDead is tested (NPCTurns.cs:665-675, 1244-1257, 1307-1320). The kill is caught at the next StartPCTurn safety net, which then overwrites CombatOver (CORE-003). PC orchestrators test only victory, and only when target.Team == Enemy (CombatFlowService.cs:395). NPCExecuteCharge is the only NPC path with a victory check (SupportActions.cs:2004-2010). See CORE-037 for the defeat-side predicate. *Seen in Play mode 2026-10-07:* the scenario harness (docs/TESTING.md 3.4) runs the Quick Start party as AI-run actors against two goblins; in 10 of 20 seeds (`smoke/soak-mini`, `sweep=20`) a party member dropped the last goblin through the NPC attack path and the game never ended combat, so the harness detected the end itself (its `combat-end-detected` invariant is waived by this issue). Kills through `NPCExecuteCharge` ended combat normally. *Reproduced by scenario:* the AI-vs-AI soak (`soak/dmg-random-encounters`, seeds 1-50, batch 20261007-204349, docs/TESTING.md 3.5): 18 of 50 fights ended VictoryUndetected with `cause=hp<=0` (for example seeds 2, 4, 9 and 10 of run 20261007-204356).
- **CORE-012** · **Med** — **Turn advancement is synchronous and re-entrant.** `NextInitiativeTurn` -> `TurnService` -> `OnTurnStarted` -> `StartPCTurn` or the NPC coroutine runs synchronously, and a combatant that must skip (`ShouldSkipTurnDueToHPState`) calls `NextInitiativeTurn` again at once. Each dying or helpless combatant adds stack frames, `OnNewRound` can fire mid-chain, and new callback code runs inside the previous turn's stack. *Evidence:* Assets/Scripts/_Core/GameManager.cs:3764-3802, 3948-3998; Assets/Scripts/Services/TurnService.cs:176-243. *Fix:* Defer turn advancement by one frame (a coroutine yield or a queued advance in Update).
- **CORE-013** · **Med** — **`ResetCombatStateForNextEncounter` kills every coroutine on GameManager.** It calls `StopAllCoroutines()` on GameManager and TurnService, silently stopping AIService, Charmed/Confused/Frightened controller and summon-despawn coroutines, including a despawn that has not yet removed its summon from `NPCs`. *Evidence:* Assets/Scripts/_Core/GameManager.cs:1097-1098, 1259, 3662; Assets/Scripts/Combat/Behaviors/CharmedBehaviorController.cs:122; Assets/Scripts/Spell/Resolution/GameManager.SpellCasting.cs:403. *Fix:* Run long-lived coroutines on their own MonoBehaviour, or stop only combat coroutines by handle.
- **CORE-014** · **Med** — **`IsPC` means "player-controlled", not "on the party's team".** `GameManager.IsPC(c)` returns `c.IsControllable`, so a dominated foe gets a PC turn with its NPC panel highlighted. `AreAllNPCsDead` counts only active `NPCs` with `Team == Enemy`, so enemies outside `NPCs` or NPCs switched to the player team are ignored for victory. *Evidence:* Assets/Scripts/_Core/GameManager.cs:670-674, 3377-3398, 4067-4079. *Fix:* Use `IsControllable` for input routing and `Team` for hostility; never use `IsPC` as a team check. *Parity audit 2026-10-07:* Parity audit 2026-10-07: other places where allegiance decides who chooses: Wish UI (GameManager_Spells_W.cs:1047, 1117), the Wall of Ice disruption prompt (W.cs:504), Blindness/Deafness (GameManager.SpellCasting.cs:6470) and the Dimension Door destination (GameManager_Spells_D.cs:517) branch on IsPlayerControlled (a Team alias, CharacterController.cs:244-283). Summons copy controllability from allegiance (SpellCasting.cs:310-311; LionsShieldBehavior.cs:283 via SetTeam). As a result PC-cast summons get the PC turn path (no compulsions, effects before the skip gate) and Player-team AI swarms get the NPC path.
- **CORE-015** · **Med** · Player-visible — **Every victory ends with an automatic full rest that also revives dead PCs.** `RestorePartyAfterCombat` sets HP to max with no `IsDead` skip, restores spell slots and resets rage, turn undead and other per-day abilities and items. PCs move to hard-coded cells (3,6), (3,9), (3,12), (3,15), a list duplicated in `SetupCreatedCharacters`. *Evidence:* Assets/Scripts/_Core/GameManager.cs:868-1043, 1872-1878; Assets/Scripts/_Core/GameManager.LootCollection.cs:290-294. *Fix:* Make the full rest configurable and move the PC start cells into one shared constant.
- **CORE-016** · **Med** — **`DND35e.Identifiers` duplicates damage, ability and save enums with different ordinals.** Its `DamageType` starts Slashing=0 (global: Untyped=0) and its `AbilityScore` starts Strength=0 (global `AbilityType`: None=0), so never cast between them by int; `SaveType` is also defined twice. *Evidence:* Assets/Scripts/Utilities/DamageType.cs:7-18; Assets/Scripts/Combat/Core/DamageModel.cs:27-41; Assets/Scripts/Spell/Casting/SpellSaveResolver.cs:32-37. *Fix:* Delete the three Identifiers enums with their `IdentifierExtensions` and `EnumTest` users (or rename them) and merge `SaveType`.
- **CORE-017** · **Med** · Player-visible — **Effect sources are matched by display name, and names are not unique.** `ConditionService.ResolveSourceCharacter`, `DispelMagicService`'s own-spell auto-success and AIService's turned/charm fallbacks compare names, but NPCs are not numbered (two goblins are both "Goblin") and two quick-start PCs are both "Kael". The wrong source can be resolved, or a dispel can auto-succeed against another caster's spell. *Evidence:* Assets/Scripts/Services/ConditionService.cs:620-637; Assets/Scripts/Services/DispelMagicService.cs:203-204. *Fix:* Store a source reference or unique id on `StatusEffect` and `ActiveSpellEffect` and compare that.
- **CORE-018** · **Low** — **`CurrentPhase` reads `TurnPhase.PCTurn` before the first combat.** It keeps the enum default until `StartCombat`, so raw `CurrentPhase == TurnPhase.PCTurn` checks are true out of combat and `EnsurePartyStashInitialized` never unlocks the stash before the first combat. *Evidence:* Assets/Scripts/_Core/GameManager.cs:207, 282-293, 849-866, 3701. *Fix:* Set an explicit out-of-combat phase in Awake; prefer `ActivePC`/`IsPlayerTurn` over raw phase checks.
- **CORE-019** · **Low** — **Static state would survive Play sessions if domain reload were disabled.** `DungeonEncounterTableManager._tables`, `DungeonEncounterSpawner._spawnCounter`, `LineOfEffectService._blockers` and `PlanarTravelSystem._planeDatabase` have no `[RuntimeInitializeOnLoadMethod]` reset, and the existing `ClearAll`/`ResetCounter`/`Reset` methods have no production callers; latent while domain reload is on. *Evidence:* Assets/Scripts/Encounters/DungeonEncounterTableManager.cs:42, 979-984; ProjectSettings/EditorSettings.asset:27. *Fix:* Add `SubsystemRegistration` resets before enabling Enter Play Mode Options.
- **CORE-020** · **Low** — **Service wiring uses `??`, `??=` and `?.` on UnityEngine.Object fields.** Awake wires 18 services as `_x ??= GetComponent<T>() ?? AddComponent<T>()` and some are called through `?.`, which ignore Unity's fake-null, so a destroyed service would be reused and calls could throw `MissingReferenceException`. Latent: MainScene serializes none of these fields (not verified in Play mode). *Evidence:* Assets/Scripts/_Core/GameManager.cs:494-566; Assets/Scripts/Spell/Resolution/GameManager.DispelCounterspell.cs:24, 51-63. *Fix:* Use explicit `if (_x == null)` checks for UnityEngine.Object fields.
