# Known issues: Runtime loop and core (CORE-)

## Bugs and rules deviations

- **CORE-002** · **Med** · Player-visible — **An ordinary victory or defeat skips the `OnCombatEnded` cleanup.** `EvaluateCombatEnd` ends a won or lost fight through `HandleCombatVictoryDetected`/`HandleCombatDefeatDetected` and the later reset goes through `TurnService.ForceResetWithoutCallbacks`, so `AIService.ClearAuraSaveImmunities`, `FrightfulPresenceLedger.Clear`, `EffectService.ClearAll`, `ConditionService.CleanupOnCombatEnd`, the bardic-music stop and the `CombatEndedEvent` publish (all in `GameManager.OnCombatEnded`) run only when the initiative order runs dry; the defeat New Party path repeats only some of them. Aura immunities are keyed by instance ID on reused NPC slots, so a PC's immunity can carry into a later encounter. *Evidence:* Assets/Scripts/_Core/GameManager.CombatEnd.cs:257-299, 338-339; Assets/Scripts/Services/TurnService.cs:284-310; Assets/Scripts/_Core/GameManager.cs:1206, 3826-3878. *Fix:* Extract that cleanup into one method called from victory, defeat and `ResetCombatStateForNextEncounter`.
- **CORE-004** · **Med** · Player-visible — **A test encounter preset permanently replaces the created party.** The `Configure*TestParty` methods re-`Init` PC1-PC3 with hard-coded stats (32 `PCn.Init` calls) and the creation data is not stored, so a later normal preset only reactivates the PC objects and the test characters stay. *Evidence:* Assets/Scripts/_Core/GameManager.TestConfigs.cs:1889-1895; Assets/Scripts/_Core/GameManager.cs:723-749, 1772-1853. *Fix:* Snapshot the party before a test preset and restore it for normal presets, or hide test presets behind a dev flag.
- **CORE-005** · **Med** · Player-visible — **Initiative tie-break comparator is inconsistent.** `TurnService.SortInitiativeOrder` breaks full ties with `Random.Range(0, 2)` inside the `List.Sort` comparator, so `Compare(a, b)` and `Compare(b, a)` can disagree. Up to 16 combatants this only randomizes tie order; above 16 with exact ties the sort can misbehave or throw (not verified in Play mode). *Evidence:* Assets/Scripts/Services/TurnService.cs:143-155. *Fix:* Pre-roll a tiebreak value per `InitiativeEntry` and compare on it.
- **CORE-035** · **Med** · Player-visible — **Daily recovery never runs: ability damage and disease are permanent.** EffectService.ProcessDailyEffects (disease progression, 1 point/day ability-damage recovery) runs only when one combat's round counter hits a multiple of RoundsPerDay = 14400, and TurnService restarts rounds at 1 each combat; CharacterStats.ApplyCompleteRest has no non-test caller and the post-combat rest does not heal ability damage. Ability damage therefore accumulates across encounters and diseases never progress or recover. *Evidence:* Assets/Scripts/_Core/GameManager.cs:204, 3779-3780; Assets/Scripts/Spell/Effects/EffectService.cs:782-796; Assets/Scripts/Character/Stats/CharacterStats.cs:2143; Assets/Scripts/_Core/GameManager.cs:844-1031. *Fix:* Drive ProcessDailyEffects (or ApplyCompleteRest) from the rest/day clock, e.g. once per RestorePartyAfterCombat or per in-game day, instead of the per-combat round count.
- **CORE-036** · **Med** · Player-visible — **Post-combat rest erases all negative levels, including resurrection level loss.** RestorePartyAfterCombat calls RemoveAllConditions and ClearAllConditions, which remove every EnergyDrained stack, including the permanent (-1 duration) negative level that Resurrection and Wish resurrection apply as their level-loss cost. There is no 24-hour Fortitude save and no conversion to real level loss, so energy drain and resurrection penalties vanish after one fight. *Evidence:* Assets/Scripts/_Core/GameManager.cs:924-925; Assets/Scripts/Services/ConditionService.cs:104-124; Assets/Scripts/Spell/Resolution/GameManager_Spells_Phase2.cs:620; Assets/Scripts/Spell/Special/WishExecutor.cs:583. *Fix:* Exclude EnergyDrained from the rest wipe, add the 24-hour Fortitude save per negative level, and apply resurrection cost as real level loss.

## Unreachable or stubbed features

- **CORE-007** · **Low** · Player-visible — **HP calculation mode (Roll/Average/Maximum) has no settings UI.** `GameSettings.hpCalculationMode` (default Roll) is set only by the LeftCtrl+H debug hotkey and read only on level-up, and `GameSettings.Instance` creates a DontDestroyOnLoad GameObject when none exists. *Evidence:* Assets/Scripts/_Core/GameSettings.cs:22-53; Assets/Scripts/Utilities/DebugCommands.cs:21-54; Assets/Scripts/Character/Stats/CharacterStats.cs:4814-4825. *Fix:* Add a settings panel or keep it debug-only, and make the mode a plain static or ScriptableObject setting.
- **CORE-008** · **Low** — **Planar travel and creature trapping are unwired scaffolding.** GameManager instantiates `PlanarTravelSystem` and `CreatureTrapSystem`, but only four setup and item-data helpers are called; `PlaneShift`, `CreateGate`, `TrapCreature` and the rest have no external caller. Latent defects: gates expire on `Time.time`, range checks use `Vector3.Distance`, `TrapCreature` never clears grid occupancy, and plane state is separate from `GameManager.CurrentPlane`. *Evidence:* Assets/Scripts/World/PlanarTravelSystem.cs:207, 704; Assets/Scripts/World/CreatureTrapSystem.cs:222-226. *Fix:* Treat as unimplemented; fix these before wiring anything to them.

## Development traps

- **CORE-009** · **Med** — **`GameManager.Awake` runs before its scene references are assigned.** `SceneBootstrap.SetupGameManager` assigns `Grid`, PCs, NPCs and `CombatUI` after `AddComponent<GameManager>()`, so Awake gives `MovementService` a null Grid and `InputService` a null camera (`Start` repairs both). New Awake code that dereferences these will fail. *Evidence:* Assets/Scripts/_Core/SceneBootstrap.cs:1001-1015; Assets/Scripts/_Core/GameManager.cs:483-583, 610-620. *Fix:* Initialize field-dependent services in Start or a post-assignment Init, or pass lazy getters.
- **CORE-010** · **Med** — **Most `GameEventSystem` events are never published.** Of the 20 event structs in GameEventSystem.cs only `CombatStartedEvent`, `TurnStartedEvent`, `NewRoundEvent`, `TurnEndedEvent`, `AttackResolvedEvent` and `CombatEndedEvent` are published (`CombatEndedEvent` not on normal victory or defeat, CORE-002), so subscribing to `DamageTakenEvent` or the other 13 never fires; the two structs defined beside the dormant scaffolding, `CombatStateChangedEvent` (CombatStateMachine.cs) and `CommandExecutedEvent` (CommandProcessor.cs), are published only by that dormant code (CORE-029). The only subscriber is `WallOfFireAreaEffect` (`TurnStartedEvent`). *Evidence:* Assets/Scripts/_Core/GameEventSystem.cs:123-300; Assets/Scripts/_Core/GameManager.cs:3668, 3723, 3755, 3846, 3963; Assets/Scripts/_Core/GameManager.AttackResolved.cs:162; Assets/Scripts/Spell/AreaEffects/WallOfFireAreaEffect.cs:645. *Fix:* Publish events at their call sites or delete unused structs, and publish `CombatEndedEvent` from one end-combat path.
- **CORE-012** · **Med** — **Turn advancement is synchronous and re-entrant.** `NextInitiativeTurn` -> `TurnService` -> `OnTurnStarted` -> `StartPCTurn` or the NPC coroutine runs synchronously, and a combatant that must skip (`ShouldSkipTurnDueToHPState`) calls `NextInitiativeTurn` again at once. Each dying or helpless combatant adds stack frames, `OnNewRound` can fire mid-chain, and new callback code runs inside the previous turn's stack. *Evidence:* Assets/Scripts/_Core/GameManager.cs:3700-3760, 3932-4004; Assets/Scripts/_Core/GameManager.NPCTurns.cs:53-64; Assets/Scripts/Services/TurnService.cs:195-248, 264-280. *Fix:* Defer turn advancement by one frame (a coroutine yield or a queued advance in Update).
- **CORE-013** · **Med** — **`ResetCombatStateForNextEncounter` kills every coroutine on GameManager.** It calls `StopAllCoroutines()` on GameManager and TurnService, silently stopping AIService, Charmed/Confused/Frightened controller and summon-despawn coroutines, including a despawn that has not yet removed its summon from `NPCs`. *Evidence:* Assets/Scripts/_Core/GameManager.cs:1098-1099; Assets/Scripts/Combat/Behaviors/CharmedBehaviorController.cs:88-122; Assets/Scripts/Spell/Resolution/GameManager.SpellCasting.cs:304-356, 435. *Fix:* Run long-lived coroutines on their own MonoBehaviour, or stop only combat coroutines by handle.
- **CORE-014** · **Med** — **`IsPC` means "player-controlled", not "on the party's team".** `GameManager.IsPC(c)` returns `c.IsControllable`, so any controllable NPC (a summon of a controllable Player-team caster, or an allied creature of the Ogre Battle, Celestial or Fiendish test presets) gets a PC turn with its NPC panel highlighted; domination and charm do not change `IsControllable`. Combat end no longer depends on it: `GameManager.EvaluateCombatEnd` counts every active combatant by `Team` (CORE-011, 2026-10-08). *Evidence:* Assets/Scripts/_Core/GameManager.cs:659-662 (`IsPC`), 3984 (`StartPCTurn`); Assets/Scripts/_Core/GameManager.NPCSetup.cs:453-490. *Fix:* Use `IsControllable` for input routing and `Team` for hostility; never use `IsPC` as a team check. *Parity audit 2026-10-07 (refreshed 2026-11-16):* other places where allegiance decides who chooses: Wish UI (GameManager_Spells_W.cs:1066, 1132), the Wall of Ice disruption prompt (W.cs:515) and Blindness/Deafness (GameManager.SpellCasting.cs:4503) branch on IsPlayerControlled (a Team alias, CharacterController.cs:240-290); the Dimension Door destination no longer does (CastChoices, batch 11). `SpawnSummonedCreature` (GameManager.SpellCasting.cs:208-209, which the Lion's Shield lion also takes through `SpawnItemSummon` since batch 12 step 24) makes a summon controllable when its caster is Player-team and controllable. As a result such summons take the PC (UI) turn path, and the summons and swarms of Player-team AI casters the NPC path; the compulsion pass and the turn-start effects are the same on both paths since batch 12 step 7 (`BeginActingTurn`, GameManager.TurnStart.cs).
- **CORE-015** · **Med** · Player-visible — **Every victory ends with an automatic full rest that also revives dead PCs.** `RestorePartyAfterCombat` sets HP to max with no `IsDead` skip, restores spell slots and resets rage, turn undead and other per-day abilities and items, and ends every condition and a hostile Dominate Person or Command Undead on a PC (since 2026-10-14, so that it cannot hold the PC out of the party side in the next fight, CORE-038; SPL-140). PCs move to hard-coded cells (3,6), (3,9), (3,12), (3,15), a list duplicated in `SetupCreatedCharacters`. *Evidence:* Assets/Scripts/_Core/GameManager.cs:844-1031, 1873-1880; Assets/Scripts/_Core/GameManager.LootCollection.cs:302. The RAW recovery that should replace it includes the aftermath of a fight both sides lost at once (delegated RAW reading 2026-10-14, formerly CORE-038 part 3; docs/systems/RULES_COVERAGE.md 4.1): the fight is decided when the PHB p.145 roll-out ends (a PC stable or better wins it), and afterwards an untended PC that stabilized on its own makes the PHB p.146 hourly 10% roll to wake (else it loses 1 hit point) and, once awake, the daily 10% roll to start natural healing (else 1 hit point); a PC stabilized by a Heal check or magic follows "Recovering with Help"; any conscious PC can give first aid (Heal DC 15, PHB p.75) to stop the loss; a party left with no surviving PC goes to the defeat flow, the fight staying recorded as won. No flag records today whether a stable character stabilized on its own or was tended. *Fix:* Make the full rest configurable and move the PC start cells into one shared constant; for RAW, replace it with natural healing and the PHB p.146 recovery above, with a per-character flag for how it stabilized (whether the victory screen shows before or after those rolls is the owner's presentation choice).
- **CORE-016** · **Med** — **`DND35e.Identifiers` duplicates damage, ability and save enums with different ordinals.** Its `DamageType` starts Slashing=0 (global: Untyped=0) and its `AbilityScore` starts Strength=0 (global `AbilityType`: None=0), so never cast between them by int; its `SavingThrow` duplicates the global `SaveType`, which is itself defined twice (the global enum and the nested `SavingThrowResolver.SaveType`). *Evidence:* Assets/Scripts/Utilities/DamageType.cs:7-18; Assets/Scripts/Utilities/AbilityScore.cs:7-15; Assets/Scripts/Utilities/SavingThrow.cs:6-11; Assets/Scripts/Combat/Core/DamageModel.cs:27-41; Assets/Scripts/Character/Skills/Skill.cs:130; Assets/Scripts/Spell/Casting/SpellSaveResolver.cs:32-37; Assets/Scripts/Services/SavingThrowResolver.cs:21. *Fix:* Delete the three Identifiers enums with their `IdentifierExtensions` and `EnumTest` users (or rename them) and merge the nested `SavingThrowResolver.SaveType` into the global `SaveType`.
- **CORE-017** · **Med** · Player-visible — **Effect sources are matched by display name, and names are not unique.** `ConditionService.ResolveSourceCharacter`, `DispelMagicService`'s own-spell auto-success, AIService's turned and frightened-source fallbacks and `CharmRules`' charm fallbacks (used when a condition carries no `Source` reference) compare names, but NPCs are not numbered (two goblins are both "Goblin") and two quick-start PCs are both "Kael".
