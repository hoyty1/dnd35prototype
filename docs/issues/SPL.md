# Known issues: Spells and metamagic (SPL-)

## Bugs and rules deviations

- **SPL-008** · **Med** · Player-visible — **Per-class spell levels are ignored when casting and preparing.** About 250 non-test reads use `SpellData.SpellLevel` instead of `GetSpellLevelFor(class)`, so a Bard with See Invisibility (Bard 3) or a Sorcerer with Bestow Curse (Sor/Wiz 4) can never cast it, and InitWizard drops Bestow Curse and Contagion. The save DC already uses the casting class's level (`SpellSaveDCRules.GetEffectiveSpellLevel`, SPL-001, 2026-10-09); the generic spell log line and Concentration still print and use `SpellLevel` (since batch 11 step 13 the entangled check's DC uses the casting class's level, `GameManager.GetEntangledCastingSpellLevel`; the defensive and grappled DCs, `ConcentrationService.GetDefensiveCastingDC` and `GetGrappledCastingDC`, still use `SpellLevel`). Since 2026-10-14 (CRE-062) `InitCleric` leaves off the known list every cleric spell whose cleric level differs from its `SpellLevel` (Blindness/Deafness, Continual Flame, Greater Magic Weapon, Locate Object, Obscure Object), so clerics cannot prepare them until slots use per-class levels; a domain slot already uses the domain level, but a spell in it is cast at its cleric-list or base level (Resist Energy, Fire 3, casts as a 2nd-level spell). *Evidence:* `Assets/Scripts/Spell/Data/SpellData.cs:51-134`, `Assets/Scripts/Spell/Components/SpellcastingComponent.cs:540-543,2120,2617`. *Fix:* resolve the casting class per cast and use `GetSpellLevelFor(class)` for slots, CanCast/SpendSlot, the spellbook filter and concentration (`SpellSaveDCRules.ResolveCastingClass` already picks the class for the DC).
- **SPL-009** · **Med** · Player-visible — **School strings with a subschool or descriptor break most school comparisons.** 40 spells store text such as "Evocation [Fire]" in `School`, which exact compares miss: an Evocation specialist cannot put Fireball in the specialist slot, and prohibited-school checks never block them. Spell Focus now parses the school (`FeatManager.GetSpellFocusDCBonus` through `SpellSchoolUtils.Parse`, SPL-001, 2026-10-09). *Evidence:* `Assets/Scripts/Character/Specialization/WizardSpecialization.cs:97-111`. *Fix:* compare with `SpellSchoolUtils.Parse(spell.School)`, or split School into an enum plus subschool and descriptor fields.
- **SPL-010** · **Med** · Player-visible — **Enlarge Spell does not extend standard ranges, and it doubles area.** It doubles `RangeSquares`, which `GetRangeSquaresForCasterLevel` ignores except for Custom range, so 116 Close/Medium/Long and 92 Touch spells pay +1 level for nothing (the AI's metamagic planner, since batch 11 step 28, measures an Enlarged candidate's range as the cast does, `AiMetamagicPlanner.RangeSquaresFor`, so it makes no Enlarged candidate of such a spell). It also doubles `AoESizeSquares`/`AreaRadius` (quadrupled with Widen), and its test checks only `RangeSquares`. *Evidence:* `Assets/Scripts/Spell/Casting/SpellCaster.cs:786-805,837-851`, `Assets/Scripts/Spell/Data/SpellRanges.cs:27-57`. *Fix:* add a range multiplier that GetRangeSquaresForCasterLevel honors, limit CanEnlarge to Close/Medium/Long, and drop the area doubling.
- **SPL-011** · **Med** · Player-visible — **Multiclass characters with a spontaneous class cannot cast their prepared spells.** CanCastSpell, GetCastablePreparedSpells and CastSpellFromSlot return from the IsSpontaneousCaster branch (and so, since SPL-123 was fixed on 2026-10-14, does CanCast, the NPC cast executor's and the counterspell check, so the NPC path refuses the same prepared spells as the PC path instead of committing the action and failing to spend), and RestoreAllSlots returns early for spontaneous and partial casters, so a Wizard/Sorcerer never casts prepared spells and a Cleric/Paladin never regains them.
