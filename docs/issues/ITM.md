# Known issues: Items, store, crafting and treasure (ITM-)

## Bugs and rules deviations

- **ITM-081** · **Med** · Player-visible — **The pre-combat inventory counts a potion or scroll stack as one item when moving it.** `PreCombatInventoryUI.ItemStackGroup.Quantity` counts ItemData objects, but a character's potions and scrolls merge into one ItemData with `StackCount` up to 20 (`Inventory.AddItem`), and a stack moved to the stash stays one object. So the stash shows such a stack as x1, the quantity prompt offers 1, and moving "1" moves the whole stack (`TransferStackFromInventoryToStash` and `TransferStackFromStashToSelectedCharacter` remove and add whole objects). Nothing is lost; the counts and the amount moved are wrong. Found 2026-10-14 while fixing ITM-003, which fixed the same counting in the store's sell list. *Evidence:* Assets/Scripts/UI/Inventory/PreCombatInventoryUI.cs:61-68, 2027, 2540-2680. *Fix:* count `StoreSelling.UnitsIn` per instance and move part of a stack with `Inventory.RemoveUnits` / `PartyStash.RemoveUnits` plus a cloned partial stack for the destination.
- **ITM-005** · **Med** · Player-visible — **Using any stored item costs a full-round action.** `GameManager.GetItemUseActionType` always returns "FullRound" (TODO), and using a consumable, picking up an item and casting from a scroll or wand all go through it. RAW: retrieving or picking up an item is a move action; drinking a potion or using a scroll or wand is a standard action. *Evidence:* Assets/Scripts/_Core/GameManager.cs:4415-4425, 4427-4477. *Fix:* return Move + Standard (Standard if already in hand) per item type, and Move for pickup. Pinned by the scenarios `rules/cast-scroll-ui` and `rules/cast-wand-ui` (batch 11 step 3, 2026-10-15: the item use is charged as one full-round action, `ActionEconomy.FullRoundActionUsed`; RAW the move and standard actions leave no action either, so the pin reads that flag); the fix rewrites that pin as a plain expectation. A spell whose casting time is longer than the item's action takes that time instead (DMG p.213: the casting time of a spell is the time to activate the same power in an item; ITM-086).
- **ITM-006** · **Med** · Player-visible — **Item spell resistance and Freedom of Movement stay after unequip.** Inventory sets `SpellResistance = Max(SpellResistance, WondrousGrantedSR)` and never restores the base, so a Mantle of Spell Resistance's SR persists and blocks allies' SR-allowing buffs. `ResetRingBonuses` also never clears `FreedomOfMovementActive`, which is mostly cosmetic. *Evidence:* Assets/Scripts/Equipment/Inventory/Inventory.cs:898-919 (`ResetRingBonuses`), 983-987, 1122-1125. *Fix:* compute effective SR as max(base, item) at read time and derive FoM-active from `RingGrantsFreedomOfMovement`.
