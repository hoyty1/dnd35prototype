# Known issues: Items, store, crafting and treasure (ITM-)

## Bugs and rules deviations

- **ITM-081** · **Med** · Player-visible — **The pre-combat inventory counts a potion or scroll stack as one item when moving it.** `PreCombatInventoryUI.ItemStackGroup.Quantity` counts ItemData objects, but a character's potions and scrolls merge into one ItemData with `StackCount` up to 20 (`Inventory.AddItem`), and a stack moved to the stash stays one object. So the stash shows such a stack as x1, the quantity prompt offers 1, and moving "1" moves the whole stack (`TransferStackFromInventoryToStash` and `TransferStackFromStashToSelectedCharacter` remove and add whole objects). Nothing is lost; the counts and the amount moved are wrong. Found 2026-10-14 while fixing ITM-003, which fixed the same counting in the store's sell list. *Evidence:* Assets/Scripts/UI/Inventory/PreCombatInventoryUI.cs:61-68, 2027, 2540-2680. *Fix:* count `StoreSelling.UnitsIn` per instance and move part of a stack with `Inventory.RemoveUnits` / `PartyStash.RemoveUnits` plus a cloned partial stack for the destination.
- **ITM-006** · **Med** · Player-visible — **Item spell resistance and Freedom of Movement stay after unequip.** Inventory sets `SpellResistance = Max(SpellResistance, WondrousGrantedSR)` and never restores the base, so a Mantle of Spell Resistance's SR persists and blocks allies' SR-allowing buffs. `ResetRingBonuses` also never clears `FreedomOfMovementActive`, which is mostly cosmetic. *Evidence:* Assets/Scripts/Equipment/Inventory/Inventory.cs:1059-1085 (`ResetRingBonuses`), 1147, 1243, 1288-1291. *Fix:* compute effective SR as max(base, item) at read time and derive FoM-active from `RingGrantsFreedomOfMovement`.
- **ITM-007** · **Med** · Player-visible — **Sell prices of enhanced weapons and armor are wrong.** `StoreInventory.ResolveBaseValue` prefers the store price for the Id, and crafted upgrades keep the mundane Id, so a crafted +3 longsword sells for 7 gp. ## Development traps

- **ITM-029** · **Med** · Player-visible — **There are two unconnected gold pools.** The store, loot and party gold use `EconomyService.PartyGold`. Crafting and costly material components spend per-character `CharacterStats.ComponentGold`, which starts at 1000 for a PC and refills only from crafting-failure refunds. An NPC starts with 0 since batch 11 step 17: it has priced components only as treasure (decision D3). Since batch 11 step 17, every priced material component with no item (Identify's pearl, Continual Flame's ruby dust, Restoration's diamond dust, ...) is paid from it at the cast core's Spend stage for every caster (`SpellComponentRules.SpendCostlyComponents`). Nothing moves gold between the pools. *Evidence:* Assets/Scripts/Character/Stats/CharacterStats.cs:301, 4627-4645; Assets/Scripts/Spell/Casting/Core/SpellComponentRules.cs:173-258; Assets/Scripts/_Core/GameManager.NPCSetup.cs:1108. *Fix:* spend crafting and component costs from EconomyService, or add a transfer UI.
- **ITM-030** · **Med** — **`Inventory.AddItem` drops per-instance state on stackable items.** Stackables merge by Id alone and the incoming instance is discarded, and any remainder becomes new stacks cloned from the ItemDatabase template, so a custom name, charges, baked DC or metamagic is lost. For an Id not in ItemDatabase, anything beyond one MaxStackSize is silently dropped. *Evidence:* Assets/Scripts/Equipment/Inventory/Inventory.cs:96-109, 131-138. *Fix:* build new stacks from the incoming item, not the template, and compare more than Id when merging.
- **ITM-031** · **Med** — **`ItemDatabase.CloneItem(string)` is a hand-written field copy of about 620 lines.** New ItemData fields must be added there or clones silently drop them. It already misses 4 public fields (latent): `TrueValueGp`, `IsTreasureItem`, `AppraisedValueGp` and `IsAppraised`. `SpecificItemBehavior` is copied by reference, so clones share state, and `ItemBuilder.CopyBaseProperties` is a second copy list. *Evidence:* Assets/Scripts/Equipment/Items/ItemDatabase.cs:1756-2378, 1796; Assets/Scripts/Equipment/Items/ItemBuilder.cs:902-955. *Fix:* add the 4 fields, then use MemberwiseClone plus deep copies or add a reflection test.
- **ITM-032** · **Med** — **The item catalog depends on an unenforced initialization order.** Rings, rods and wondrous items enter ItemDatabase only through `RegisterAll*` calls made by hand after `ItemDatabase.Init()`, so tests that call only Init miss them. `CraftableItemRegistry.Init()` scans the catalog once and latches, so if it ran before those calls, rods, wondrous items and staves would stay uncraftable (latent today). *Evidence:* Assets/Scripts/Equipment/Items/ItemDatabase.cs:16-43; Assets/Scripts/Crafting/CraftableItemRegistry.cs:34-56. *Fix:* have ItemDatabase.Init call the RegisterAll* hooks.
- **ITM-033** · **Med** — **Item kind is stored twice, as `ItemType` and IsXxx flags, which disagree.** There is no `ItemType.Rod`: rods are Type=Wondrous with `IsRod = true` and `IsWondrous = false`, so `IsWondrousItem` (checks Type) is true while `IsWondrous` is false. Wands, scrolls and potions are all Type=Consumable, told apart by flags. *Evidence:* Assets/Scripts/Equipment/Items/ItemData.cs:9-19, 393, 519, 697, 1357; Assets/Scripts/Equipment/Rods/RodFactory.cs:54-70. *Fix:* classify by the IsRod/IsWand/IsStaff/IsWondrous flags, never by ItemType alone.
- **ITM-034** · **Med** — **Wand charges are stored twice.** `ItemData` and `WandData` each have `CurrentCharges`/`MaxCharges`. The four wand-use sites in GameManager decrement both by hand. `WandValidator` reads only ItemData, while the store's sell price (`StoreInventory.GetSellPrice` via `StoreSelling.SellValue`) prefers WandData. *Evidence:* Assets/Scripts/_Core/GameManager.cs:5585-5586, 6302-6303, 6424-6425, 6439-6440; Assets/Scripts/Equipment/Inventory/WandValidator.cs:88; Assets/Scripts/Equipment/Store/StoreSelling.cs:78-79. *Fix:* forward the ItemData properties to `Wand` when present, or add one ConsumeWandCharge helper.
- **ITM-035** · **Med** — **Enhancement bonus has two fields and can come from the item name.** `ItemDatabase.Register` cross-fills `enhancementBonus` and `EnhancementBonus`, but unregistered (treasure, crafted, runtime) items skip that. `ItemData.ResolveEnhancementBonus` clamps to 0-5 and, if both fields are 0, parses "+N" (prefix or suffix) from Name, so renaming an item can change its bonus. *Evidence:* Assets/Scripts/Equipment/Items/ItemData.cs:1526-1578; Assets/Scripts/Equipment/Items/ItemDatabase.cs:1590-1601. *Fix:* collapse to one field and drop name parsing or limit it to legacy-data migration.
- **ITM-036** · **Med** — **Other legacy and canonical duplicates can disagree.** Examples: ItemData's wand and scroll fields vs ScrollData/WandData, `AttackRange`/`HasReach` vs `ReachSquares`/`IsReachWeapon`, `EquipSlot.Armor` vs ArmorRobe, and 5 legacy item IDs such as `potion_healing` and `rope`. Code that writes one side can disagree with code that reads the other. *Evidence:* Assets/Scripts/Equipment/Items/ItemData.cs:40, 197-205, 354-406; Assets/Scripts/Equipment/Items/ItemDatabase.cs:1628-1648. *Fix:* migrate callers to the canonical fields and IDs, then remove the aliases.
- **ITM-037** · **Low** — **StoreInventory changes shared ItemDatabase templates while building its catalog.** `AddEnhancedVariants` and the string `Add()` overload (for unpriced templates) write store prices into live templates' `BasePriceGp`, so later `Get`/`CloneItem` prices depend on whether the store was initialized. *Evidence:* Assets/Scripts/Equipment/Store/StoreInventory.cs:162-167, 276-296. *Fix:* keep store prices only in `_priceLookup`/StoreItemEntry and set template prices at registration.
- **ITM-038** · **Low** — **A failed `ItemDatabase.Init()` cannot be retried.** Init sets `_initialized = true` before populating `_items` (to stop re-entrant recursion) and has no try/catch, so an exception partway leaves a permanently half-built catalog. *Evidence:* Assets/Scripts/Equipment/Items/ItemDatabase.cs:18-43. *Fix:* use a separate `_initializing` guard and set `_initialized` only after success.
- **ITM-039** · **Low** — **The `CharacterInventory` class is unrelated to the `InventoryComponent.CharacterInventory` field.** The class is a MonoBehaviour adapter; the field is an `Inventory`. Get the model with `actor.InventoryComp.CharacterInventory` (about 15 call sites) or `GetInventory()` on the adapter. *Evidence:* Assets/Scripts/Equipment/Inventory/InventoryComponent.cs:8-19; Assets/Scripts/Equipment/Inventory/CharacterInventory.cs:7-39. *Fix:* rename the field (for example to `Inventory`) or the adapter.
- **ITM-040** · **Low** — **Equipment/SpellStorage holds only ring code.** It has the Ring of Spell Storing and Ring of Counterspells managers; ScrollData and WandData are in Equipment/Items, and the potion, scroll and wand factories and validators are in Equipment/Inventory (there is no PotionValidator). *Evidence:* Assets/Scripts/Equipment/SpellStorage/; Assets/Scripts/Equipment/Inventory/. *Fix:* none needed; navigation note.
